Public API¶

PME2 provides a public API for external scripts and other addons.

Import the running API¶

The examples use import pme, the optional short alias configured in Boot Options. When that alias is disabled, use the enabled add-on’s package name without changing the startup configuration or reloading Blender:

import bpy
import importlib

packages = [
    addon.module for addon in bpy.context.preferences.addons
    if addon.module.rsplit(".", 1)[-1] == "pie_menu_editor"
]
if len(packages) != 1:
    raise RuntimeError(f"Select the enabled PME package: {packages}")
pme = importlib.import_module(packages[0] + ".api")
print(pme.ADDON_ID)

This also works for a Blender Extension installed as bl_ext.<repository>.pie_menu_editor. If several packages are listed, identify the intended installation before editing. All examples below can use the pme variable returned by this explicit import; the short alias is not required. When using it, omit import pme from the following snippets.

Quick Start¶

import pme

# Runtime package identity (Legacy add-on or Blender Extension)
addon_id = pme.ADDON_ID

# Find a menu
pm = pme.find_pm("My Pie Menu")
pm = pme.find_pm(uid="pm_9f7c2k3h")

# Invoke a menu
pme.invoke_pm("My Pie Menu")
pme.invoke_pm(uid="pm_9f7c2k3h")

# List menus
all_menus = pme.list_pms()
pie_menus = pme.list_pms(mode="PMENU", enabled_only=True)
tags = pme.list_tags()

# Execute code
result = pme.execute("bpy.ops.mesh.primitive_cube_add()")
print(result.success, result.error_message)

# Evaluate an expression
value = pme.evaluate("len(C.selected_objects)")

# Validate JSON
result = pme.validate_json(json_string)
for err in result.errors:
    print(err.code, err.message)

Local menu editing¶

pme.editing reads and edits saved definitions from Blender’s main Python thread after PME has finished loading. It can be called from the Console, Text Editor, or an existing Blender tool that runs Python there. These functions do not execute the authored actions or save Preferences to disk. The API is Experimental.

Use an initialized GUI session for menu creation and editing. PME’s --background registration does not initialize the temporary Preferences and editor state used by these workflows; background JSON validation is separate. There is no public initialization-status/wait API yet. A fixed startup delay, or retrying arbitrary RuntimeError exceptions, does not prove readiness. Wait for PME’s normal Preferences editor to be available before running the authoring examples in the Console or Text Editor.

The compatibility boundary is the UID-addressed operation, its documented inputs, conflict checks, and observable result. Internal implementations may change while preserving the saved format and normal UI normalization. Read the operation’s result and diagnostics to distinguish completion, rejection, partial application, and an unknown outcome; after an unexpected exception or unknown outcome, read again before deciding whether to retry. Changes to failure residual state or stale detection are observable behavior changes, even when the function signature stays the same. A batch does not promise atomicity, Blender Undo, execution success, or disk persistence. Save through Blender’s Save Preferences when needed, then verify after restart.

When editing many menus through an external tool, use small batches and retain results and progress between calls. A tool timeout does not cancel Blender’s work or prove that nothing changed. Wait for the running call to finish, then read the target menus before deciding which changes, if any, to retry.

Move one list item¶

For an editable flat list, supply exactly one anchor UID. This moves the last item before the first while retaining every item’s UID and saved content:

before = pme.editing.read_pm(pm_uid)
result = pme.editing.move_slot(
    pm_uid, before["slots"][-1]["uid"],
    before_uid=before["slots"][0]["uid"], expected_version=before["version"],
)
print(result["status"], result["before_order"], result["after_order"])

Use after_uid to place it after another item. Already being at the requested position, including a self anchor, returns status="unchanged" and committed=False without incrementing the version or refreshing the editor. Missing or ambiguous UIDs and stale versions are rejected before moving. Malformed input raises TypeError or ValueError. Other items retain their relative order. slots contains the target’s saved values before and after; side_effects includes other changed readback values, including their indexes. Normal editor hooks run on a changed order, including Macro registration. Hook failure restores the UID order, but does not promise to revert every callback effect. Inspect the returned diagnostics and readback. A refresh exception can occur after commit: read the menu again before retrying. This does not save Preferences or provide Blender Undo.

Exchange two fixed-slot items¶

swap_slots exchanges the positions of two items in a fixed-slot menu. Each UID moves with its saved values; the intervening items stay in place. Both UIDs are resolved before writing and the version increments once. The same UID twice returns unchanged, committed=False, without changing the version. slots contains both items with before/after readback; before_order and after_order show the full order. Apply or editor-hook failure restores order, but arbitrary hook field changes can remain in the readback. It does not save Preferences or provide Blender Undo. After an exception, read back before retrying because refresh can fail after commit.

before = pme.editing.read_pm(pm_uid)
result = pme.editing.swap_slots(
    pm_uid, before["slots"][0]["uid"], before["slots"][2]["uid"],
    expected_version=before["version"],
)

Check a move or exchange without changing it¶

Pass dry_run=True to move_slot or swap_slots to use the same preflight checks as execution and the normal editor. An allowed change returns status="validated"; an already satisfied position returns "unchanged"; an unavailable destination returns "rejected" with a diagnostic reason. All three return committed=False. Layout moves use the same query mechanism, with the row targets and additional readback described below. Flat-list moves continue to accept dry_run=True; a non-None expected raises TypeError for flat-list moves and fixed-slot exchanges.

before = pme.editing.read_pm(pm_uid)
checked = pme.editing.swap_slots(
    pm_uid, before["slots"][0]["uid"], before["slots"][2]["uid"],
    expected_version=before["version"], dry_run=True,
)
print(checked["status"], checked["diagnostics"])

The query does not change saved values, UIDs, order, versions, selection or an open Slot Editor draft. It does not run editor hooks or request a refresh. before_order, after_order, and slot before / after describe the current saved state, so they remain equal; they are not a prediction of a committed move. A successful query does not reserve the destination or prove that later registration or refresh will succeed. Call the same operation without dry_run=True to execute it; the operation checks the current state again.

Read a resolved Popup insertion position¶

Pop-up Dialog and Floating Panel add_slot and move_slot results include insertion_position. For transfer_slot, read result["to"]["insertion_position"]. The shared operation records the position it resolved for both queries and execution. It describes a gap in the saved order before the operation:

Field

Meaning

Always "before"

Gap index from 0 through the number of saved slots, including structural slots

previous_slot_uid

Slot immediately before the gap, or None at the start

next_slot_uid

Slot immediately after the gap, or None at the end

row_ref

The before-state row containing the previous slot; at index 0, the markerless first row if present; otherwise None

new_row

For saved order [row, A, COLUMN, B], inserting after A resolves to index 2 between A and COLUMN; inserting before B resolves to index 3 between COLUMN and B. The result keeps structural slot UIDs, so callers can distinguish the two sides of that boundary without recalculating the input position.

A new-row target reports the before-state end index with row_ref=None. It allocates no future row reference or UID. Source removal, spacer insertion and cleanup can change the final item index. The recorded position keeps its before basis after success or failure; inspect the existing after values and orders for the actual saved result. An unchanged move can still report the requested gap, including the source UID as a neighbor.

An unresolved early rejection returns None. A rejection after position resolution can include a position; status and diagnostics determine whether the operation is allowed. Shared Popup results for swaps, removals and row operations use None, as do transfers to non-Popup menus. A fresh preflight rejection never borrows a position from the earlier check.

This field records saved insertion boundaries. General column/subrow nesting and a layout tree are not provided. Queries retain the current saved values in before_rows and after_rows; they do not predict cleanup.

Transfer contents to another menu¶

transfer_slot moves one item’s contents, including enabled, between two menus. It uses the normal Paste rules for accepted content and field conversion. The two menus must be different; use move_slot or swap_slots within one menu.

  • For a fixed destination, supply destination_slot_uid for an empty slot. The destination keeps its UID. A Sticky slot is empty when its mode is COMMAND and its command text is empty.

  • For a flat-list destination, supply exactly one of before_uid / after_uid. The inserted item receives a new UID. An empty list takes neither anchor.

  • For a Pop-up Dialog / Floating Panel destination, use before_uid / after_uid, a current row_ref with edge="START" / "END", or new_row="END". An explicit ordinary row may be empty. An empty menu also accepts no position. These forms are exclusive; a new item receives a new UID.

  • For a Panel header destination, supply header_anchor_uid with a relative before_uid / after_uid or edge="START" / "END". The header role is required for transfers even when Header Layout is on. Moving into an off header leaves it off and reports header_layout_disabled with its anchor UID.

  • use_spacer defaults to False, independently of Preferences. True uses the normal Move spacer rules for item-relative and row-edge positions. A new final row uses the existing row settings rules without an extra spacer.

  • A fixed source is cleared while retaining its UID and enabled state. A Sticky source also regains its default On Press / On Release name and empty command. A list source is removed, even when it is the last item.

  • Regular Menu labels and layout markers can be anchors, but cannot be the contents being transferred. Layout Panel anchors are not transferable items; their ordinary header items can be moved out, including from an off header.

For a flat-list destination, query first and pass the complete returned expected value to the same call:

destination = pme.editing.read_pm(destination_pm_uid)
position = ({"after_uid": destination["slots"][-1]["uid"]}
            if destination["slots"] else {})
checked = pme.editing.transfer_slot(
    source_pm_uid, source_slot_uid, destination_pm_uid,
    **position, dry_run=True,
)
if checked["status"] == "validated":
    result = pme.editing.transfer_slot(
        source_pm_uid, source_slot_uid, destination_pm_uid,
        **position, expected=checked["expected"],
    )
    print(result["status"], result["from"], result["to"])
    print(result["moved"], result["effects"], result["loss"])

For a fixed destination, replace position with {"destination_slot_uid": empty_slot_uid}. Position arguments are exclusive. For an empty or populated Panel header, use {"header_anchor_uid": panel_anchor_uid, "edge": "END"} instead. For an ordinary layout row, use {"row_ref": current_row_ref, "edge": "END"}. expected is an opaque snapshot of both menus and the relevant reference facts; keep it intact. It can be round-tripped through JSON. No separate expected_version argument is needed. Passing None skips comparison with a prior snapshot, while retaining current-state validation.

The query returns the actual unchanged values in each side’s before / after. It allocates no UID, initializes no version, and runs no editor hooks or refresh. Predicted conversions appear in effects; dynamic Macro icons and registration are observed after execution. Both saved writes happen before the editor hooks. A successful transfer increments each menu’s version once and returns the actual addresses in moved.

For a layout side, before_rows / after_rows describe its actual saved rows. The query does not predict cleanup or new UIDs. Transfer cleans up the affected insertion/removal boundaries and an emptied source row, retaining unrelated empty rows and distant spacers. If the markerless first row becomes empty, its following row marker is absorbed as in ordinary Move. This differs from the explicit remove_row operation. Moving the last content out can leave an empty menu; moving the last header item out retains the anchor and its empty header. Re-read row references after changes.

If transfer_rows_readback_failed is reported, that side’s after_rows is None; the saved operation status is retained. Read the rows again rather than retrying a transfer that already committed.

layout_panel is not copied. It remains on a fixed source, and is lost with a removed list source; loss reports the saved value and disposition. An open draft for the source, fixed destination, or a layout marker that cleanup would remove or rewrite rejects the operation. Unrelated drafts, clipboard and selection are retained. Missing or ambiguous menu references retain their raw values with warnings; uniquely resolved references that become invalid in the destination are rejected before writing.

Inspect diagnostics on rejection or failure. restored_failure means both saved item collections match their prior snapshots after recovery; Macro registration is reported separately in effects. unknown means recovery or readback could not establish that result, and unreadable after values are None. Read again before deciding what to do; do not automatically retry. Refresh failure keeps a committed result. The operation does not save Preferences to disk or provide Blender Undo.

Read and move layout items¶

For a Pop-up Dialog or Floating Panel, read_pm() also returns rows in saved order. slot_uids filters only the slots details: rows still describes the whole menu. An empty menu has rows=[]. Reading does not add row markers, repair UIDs, initialize a version, or change the layout.

Each row includes row_ref, slot_uids (including its marker, if present), has_marker, raw_text, settings, defaulted_fields, diagnostics, and spacers. Spacer entries describe saved column/subrow boundaries as well as spacing. A row without a marker has raw_text=None and default settings; its first item’s command is not treated as row settings. Unknown saved text remains available in the raw values. panel is either None or a dictionary with anchor_uid, interpreted options, header_uids, and the raw saved layout_panel value with layout_panel_present. Saved header items remain in the readback when Header Layout is off or an item is disabled.

A row_ref has kind="marker" or "first_item" and a slot_uid. It refers to the row’s current head, not a permanent row ID. Moving that head or adding or removing a marker can invalidate the reference. Use the returned after_rows or read again to obtain current references; an old reference is not redirected to a different row.

For ordinary items, the existing Move choices are available through:

  • swap_slots(pm_uid, slot_uid, other_slot_uid) to exchange two items with their UIDs and saved contents, without cleaning up empty rows or spacers.

  • move_slot(..., before_uid=...) or after_uid=... to insert an item immediately before or after another stored item.

  • move_slot(..., row_ref=..., edge="START") or edge="END" to move an item to that row’s left or right end.

  • move_slot(..., new_row="END") to move it to a new final row.

An explicit row_ref may select an empty ordinary row.

Supply exactly one destination form. Mixing forms raises ValueError; new_row is a position string, not a bool. use_spacer is an explicit bool, defaulting to False; it does not inherit the Preferences setting. Item-relative, row-end, and new-row moves retain the normal editor’s empty-row and spacer cleanup. The moved item’s UID and content, the current selection, and an open Slot Editor draft remain attached to their existing items.

Item-relative positions use the anchor’s saved index. They do not skip column, subrow, or spacer markers: after_uid=A and before_uid=B can be different positions when markers separate A and B. A self anchor or an immediately adjacent stored item that already satisfies the position returns unchanged, without adding spacers, cleaning up, incrementing the version, or refreshing. The normal Move chooser offers item-relative before/after controls alongside the existing item exchange, row-end controls, and Add Row.

This example uses a known ordinary slot_uid and a last row that accepts normal items:

before = pme.editing.read_pm(pm_uid)
row_ref = before["rows"][-1]["row_ref"]
checked = pme.editing.move_slot(
    pm_uid, slot_uid, row_ref=row_ref, edge="END",
    expected_version=before["version"], dry_run=True,
)
if checked["status"] == "validated":
    result = pme.editing.move_slot(
        pm_uid, slot_uid, row_ref=row_ref, edge="END",
        expected_version=checked["version"], expected=checked["expected"],
    )
    print(result["status"], result["after_rows"], result["structure_changes"])

Pass the complete expected from the layout Add, Remove, move, or exchange query unchanged. It compares saved contents and structure as well as order; a version alone does not detect every edit. A filtered read_pm() result or an edited settings dictionary is not a substitute. Non-None expected is not accepted for flat list moves or fixed-slot exchanges and raises TypeError.

Layout results retain the usual slots, before_order, after_order, and version, and add version_before, version_after, before_rows, after_rows, created_uids, deleted_uids, moved_uids, structure_changes, expected, and recovery. version is the resulting version. structure_changes reports the actual row and spacer changes, including cleanup beyond the source row. Dry-run before/after values remain the current saved state and the changed UID lists are empty. The query does not predict complete cleanup results or allocate future UIDs.

If final readback fails, diagnostics includes popup_readback_failed while preserving the operation’s original status and recovery. Unreadable after_order or after_rows is None, not a copy of the before value. If only row readback fails, after_order still reports the observed order. Without a final saved-state snapshot, the changed UID lists are empty rather than inferred; this does not prove that nothing changed. Read again before deciding whether to retry.

Individual header items use the Panel header positions described below. A Panel’s owning anchor cannot be removed, moved, or exchanged as an individual item.

Add, remove, move, split, and join layout rows¶

The five row operations accept Pop-up Dialog and Floating Panel. Pass current row_ref values from read_pm()["rows"]; these are references to saved row heads, not permanent row IDs. Normal editor actions and API calls use the same operation.

Operation

Saved result

add_row

Add a row marker and the menu’s default button. Use at most one position; omitting both appends, including to an empty menu. Existing row size/spacing inheritance follows Add Row.

remove_row

Remove the selected marker and all contents. Retain the next row’s marker and settings. Removing the last row leaves an empty menu.

move_row

Supply exactly one before_row_ref or after_row_ref. Move the complete row with its settings and item UIDs. No item-move cleanup runs.

split_row

The item or spacer named by before_uid starts a new right row with default settings and no new button. The left row keeps its settings. Remove one immediately preceding spacer, as in Split; retain other contents.

join_rows

The supplied rows must still be adjacent in that order. Keep the first row’s settings; remove the second marker and its whole COLUMN/ALIGNER spacers. Retain other contents and spacers.

Layout Panel Move/Remove includes its anchor and all header items, including disabled items and items hidden by Header Layout. Panel rows cannot be split or joined. Removal rejects a draft on an item being deleted; unrelated drafts, selection, and the row clipboard stay in place.

Split accepts the first item as before_uid, leaving an empty left row. It can also split at a saved structural spacer, which remains on the right. A row marker itself is not an inner split point. Column and alignment rows are accepted except when the split newly places the first ALIGNER after the first COLUMN on the right: that would lose the alignment root. The aligner_without_root rejection leaves the saved row unchanged. Selecting the alignment spacer itself can retain the root. Existing malformed rows are not automatically repaired. The normal UI keeps its existing choice placement, including no Split entry on the first item.

An explicit edit creates a missing marker only when needed to retain a row boundary. It preserves existing item UIDs and command text. A self move or an already-satisfied position is unchanged, without marker creation, version increments, or refresh. Reading and dry-run never create markers.

before = pme.editing.read_pm(pm_uid)
checked = pme.editing.add_row(
    pm_uid, expected_version=before["version"], dry_run=True,
)
if checked["status"] == "validated":
    added = pme.editing.add_row(
        pm_uid, expected_version=checked["version"], expected=checked["expected"],
    )
    print(added["status"], added["after_rows"], added["created_row_refs"])

All five operations use the complete saved expected snapshot and version described above. Dry-run reports actual unchanged values without allocating future UIDs. Apply rechecks the current rows and saved values.

Row results additionally include created_row_refs, deleted_row_refs, and moved_row_refs, derived from actual before/after rows. A moved reference means its saved start index changed, including shifts caused by another row’s edit. When a missing marker is created, structure_changes includes {"kind": "row_ref", "before": old_ref, "after": new_ref} for the retained row. Use after_rows or read again for subsequent calls. If row readback fails, the row-change lists cannot establish what changed. The same status, recovery, refresh-diagnostic, disk-save, and Undo rules as layout item operations apply.

Create a Layout Panel and edit its header¶

add_panel accepts Pop-up Dialog and Floating Panel. Use at most one current before_row_ref or after_row_ref; omit both to append, including to an empty menu. It creates the same default Panel as Add Panel: a new row and MENU anchor named Panel, an empty body target, a fresh panel ID, and both default_closed and use_header_layout set to False. A missing marker is added only where needed to retain the existing row boundary and command text.

Pass expected_version, the complete expected returned by its dry-run, and dry_run as for other layout operations. Preview allocates no UID. Use the actual after_rows, created_uids, and row references after commit. Set the anchor’s name and menu_target_uid through update_slots, using its saved UID; do not construct a layout_panel dictionary or row marker yourself.

Panel settings remain the existing update_slots fields layout_panel_default_closed and layout_panel_use_header_layout. They are strict bools. Switching an empty header from OFF to ON creates one initial button. Removing or moving out its last item leaves it empty: another Save, rename, or unchanged True does not refill it. OFF preserves all saved header items. Normal changed saves retain the editor’s anchor normalization, including enabled=True; enabled is not an update_slots input field. Slot updates keep their existing sequential, non-atomic save and failure behavior.

For header Add or Move, obtain the existing panel.anchor_uid from rows and pass it as header_anchor_uid. Combine it with exactly one position:

  • before_uid or after_uid of a saved item in that header. Saved spacers count as positions, so intervening markers are not skipped.

  • edge="START" or edge="END" to insert after the anchor or at the header’s end. Use an edge when the header is empty.

Do not combine a header position with row_ref or new_row. A Panel row reference does not implicitly mean its header. Moving from an ordinary row or another header requires header_anchor_uid; relative rearrangement inside the same header works without it. Existing relative Add within an ON header remains available without the qualifier; OFF header Add requires it.

This example moves a known ordinary slot_uid to the end of a chosen header:

before = pme.editing.read_pm(pm_uid)
panel = next(row["panel"] for row in before["rows"] if row["panel"])
anchor_uid = panel["anchor_uid"]
checked = pme.editing.move_slot(
    pm_uid, slot_uid, header_anchor_uid=anchor_uid, edge="END",
    expected_version=before["version"], dry_run=True,
)
if checked["status"] == "validated":
    moved = pme.editing.move_slot(
        pm_uid, slot_uid, header_anchor_uid=anchor_uid, edge="END",
        expected_version=checked["version"], expected=checked["expected"],
    )
    print(moved["status"], moved["diagnostics"], moved["after_rows"])

Use the same destination arguments with add_slot. swap_slots needs only its two item UIDs to exchange ordinary/header items or items in different headers; it does not apply Add or Move cleanup. A raw Panel anchor cannot be moved into another header. The owning anchor and header move or are removed together through the row operations. A second raw anchor already stored inside a header can be explicitly removed as an item; this does not authorize inserting one.

Header editing works while Header Layout is OFF and does not enable it. Inspect header_layout_disabled in diagnostics with its anchor_uid, along with the actual saved rows. Preferences shows the individual saved items for editing while runtime menus keep them hidden. The anchor menu provides Add for an empty header, and Move offers header START/END positions. Ctrl+Alt removes one header item; Delete Inactive Header remains an explicit bulk action.

Read one menu and update a slot¶

read_pm() returns ordinary Python values rather than live Blender objects. The menu dictionary contains uid, name, mode, enabled, data, description, description_is_expr, poll_cmd, hotkey, tags, version, editable_slots, and slots. Each slot contains its uid, index, and saved fields such as name, mode, text, icon, and auto_icon. index describes its current position; writes select the slot by UID. The slot’s layout_panel dictionary also records its saved Layout Panel options. Pop-up Dialog and Floating Panel definitions additionally include the complete rows structure described above.

The following example updates a known slot UID. Obtain pm_uid and slot_uid by finding the requested menu and inspecting its slots first.

before = pme.editing.read_pm(pm_uid, slot_uids=[slot_uid])
slot = before["slots"][0]
result = pme.editing.update_slots(
    pm_uid,
    {slot_uid: {
        "mode": "COMMAND",
        "cmd": "bpy.ops.wm.tool_set_by_id(name='builtin.knife')",
        "auto_icon": True,

    expected={slot_uid: slot},

after = pme.editing.read_pm(pm_uid, slot_uids=[slot_uid])

Delete one or more menus¶

delete_pms(pm_uids, *, expected=None, dry_run=False) uses the same batch deletion as the normal editor’s Selected Remove. Pass an iterable of menu UID strings, including a one-element list for one menu. A single string, an empty iterable, duplicate UIDs, and invalid input types are rejected before writing. The operation processes targets in their current collection order.

preview = pme.editing.delete_pms([pm_uid], dry_run=True)
print(preview["status"], preview["references"], preview["diagnostics"])
if preview["status"] == "ready":
    result = pme.editing.delete_pms([pm_uid], expected=preview["expected"])
    print(result["status"], result["removed_uids"], result["recovery"])

The dry-run does not change saved values, versions, selection, drafts or host registration. before and after contain the same saved values, and committed is false. It checks the current targets and returns the planned active menu; it does not reserve them or prove that teardown will succeed.

Pass the complete returned expected unchanged. It contains collection_version, collection_digest, target_digests, and references_digest. These compare the collection identity and order, the targets’ saved contents, and saved references to the targets. They can detect changes that do not increment the collection version. A stale result requires a new read and a decision about the intended deletion. Without expected, the operation uses the state at the start of the call and still rechecks it before removing each target.

References are reported but are not removed or rewritten. A surviving menu can therefore retain a broken link to a deleted menu. The report includes saved Router and Property Stack references even when disabled or incomplete. Static source inspection cannot find every dynamically constructed reference; coverage warnings do not prohibit deletion. An open draft owned by a target blocks deletion before writing. A draft owned by another menu remains intact. An active menu outside the target set keeps its UID; deleting the active menu uses the normal batch selection rule.

selection_before and selection_after distinguish the active UID, selected UIDs, and tree row. active_visible reports the current region’s last-rendered evidence (visibility_scope="last_rendered_region"), or None when unavailable. It does not prove that a refresh has already drawn the final state. Filters are not cleared to reveal a surviving menu.

Duplicate a menu¶

duplicate_pm(source_pm_uid, *, name=None, expected=None, dry_run=False) duplicates one saved menu through the normal Duplicate operation. The copy is inserted immediately after its source in collection order, regardless of the active menu or the displayed sort order.

Names retain the existing membership rules: add trims its input, remove uses the exact supplied name, and case and Unicode are preserved. A comma in an add input contributes multiple names; a comma in a remove input is not split. For example, add=["A,B"], remove=["B"] is a conflict. Single empty or "Untagged" additions are existing no-ops, reported in ignored_names; they still participate in duplicate-input checks. There is no additional name-length limit. Existing membership or a missing removal can still normalize saved raw order and duplicates, so inspect actual changes instead of comparing name sets.

read_pm()["tags"] is the sorted, unique list of names represented by the current saved raw text, without synchronization. Empty raw text returns []; a saved empty-name membership and a literal "Untagged" remain distinct. This does not change PMHandle.tag, PMItem.get_tags(), or list_tags().

Dry-run checks inputs, target resolution, and the pure name transformation. It does not synchronize, allocate UIDs, predict new definitions, or prove that a later write will succeed. Pass its complete JSON-compatible expected back unchanged: activated, targets_digest, and definitions_digest. Membership raw text, references, projection stamps, and registry definitions are compared before normal synchronization. A stale expected is rejected without writing. Empty changes or an empty target set return unchanged after this check, without synchronization or refresh.

before and after contain actual target values, including raw text, names, references, and projection stamps. changed_uids describes the batch change after synchronization. synchronized separately records the normal synchronization changes, including other menus and definitions; it can be present even when the requested batch is unchanged. These two phases are not one atomic transaction.

status

recovery.carrier_matches compares saved tag data with the stated baseline: before for synchronization failure or after_synchronize for batch failure. Optional readback or refresh failure does not reverse an already successful batch result. Missing observations and refresh deferral appear in diagnostics.

The active menu UID, selected UID set, and open draft are retained. The same Tree occurrence is retained when it remains available and refresh succeeds. Clear contents without deleting a direction¶

Use Clear rather than setting the Slot Editor’s mode to EMPTY:

before = pme.editing.read_pm(pm_uid, slot_uids=[slot_uid])
result = pme.editing.clear_slots(pm_uid, [slot_uid],
    expected_version=before["version"], expected={slot_uid: before["slots"][0]})
print(result)

Clear retains the slot’s UID, position, and enabled state, and resets contents, references, icons, and descriptions using the normal UI rules. The owning editor must support EMPTY (clear_unsupported otherwise); layout structure entries are rejected as structural_slot and need their normal layout editor. In a Regular Menu, clearing a content item leaves a separator, not a removed list item. The batch result and partial-save behavior below also apply to Clear. A refresh exception can occur after content was cleared; read the target again before retrying.

Add or remove one item¶

For a Regular Menu with at least two items, this inserts a default item after the second one. The operation returns the new UID; use update_slots() to author its contents separately. Omit both position arguments to append, or use before_uid to insert before a known item. Do not pass both anchors. The same position arguments apply to Pop-up Dialog and Floating Panel items, without skipping intervening layout markers. An empty menu accepts an addition without an anchor and does not receive an implicit row marker.

before = pme.editing.read_pm(pm_uid)
anchor_uid = before["slots"][1]["uid"]
checked = pme.editing.add_slot(
    pm_uid, after_uid=anchor_uid, expected_version=before["version"], dry_run=True,
)
if checked["status"] != "validated":
    raise RuntimeError(checked["diagnostics"])
added = pme.editing.add_slot(
    pm_uid, after_uid=anchor_uid,
    expected_version=checked["version"], expected=checked["expected"],
)
print(added)
if not added["committed"]:
    raise RuntimeError(added["diagnostics"])
new_uid = added["slots"][0]["uid"]

Regular Menu kinds are ITEM (the default), LABEL, SPACER, SEPARATOR, and COLUMN, with the same initial values as the UI. For Macro, Modal, and Stack Key, omit kind to use the editor’s normal Add initialization. Unknown or inapplicable kinds are rejected with slot_kind_unsupported.

For Pop-up Dialog and Floating Panel, omit kind or use kind="BUTTON" for a normal empty Command item. use_spacer=True adds the usual automatic spacer: before an anchor the saved sequence is new item, spacer, anchor; after it the sequence is anchor, spacer, new item. The default is False, independent of Preferences. Flat lists reject use_spacer=True with unsupported_position; Regular Menu’s kind="SPACER" remains a separate item kind. use_spacer and dry_run accept only bools, not 0, 1, or None.

Fixed-slot menus use clear_slots() instead of insertion or deletion (fixed_slots). Menus with editable_slots=False use their dedicated authoring editor. Removal can delete the last variable item and leave an empty saved list, including in Pop-up Dialog and Floating Panel. It does not insert a replacement row or item. Layout removal rejects the item currently open in the Slot Editor before writing; unrelated drafts, selection, and clipboard contents are retained.

Each call handles one item and returns before_order and after_order UID lists, version, and the target’s before/after values in slots. The added item’s before is None; the removed item’s after is None. Other changes, including shifted indexes, appear in side_effects. Remaining content items retain their UIDs and relative order. Layout cleanup is operation-specific: Add leaves markers alone, Move uses its normal empty-row/spacer cleanup, and Remove merges nearby markers and removes subrow boundaries when the affected row has fewer than two columns. Layout results include the observed after_rows and structure_changes. An automatic spacer appears in created_uids and structure changes; the new main item is always slots[0]["uid"].

For flat-list removal, expected retains its saved-field subset contract. For example, {"name": observed_name} checks only the name; {} adds no condition. The following example passes all observed target fields:

before = pme.editing.read_pm(pm_uid, slot_uids=[new_uid])
removed = pme.editing.remove_slot(pm_uid, new_uid,
    expected_version=before["version"], expected=before["slots"][0])
print(removed)

For layout removal, use the complete saved snapshot from a removal query instead of a read_pm()["slots"] entry:

checked = pme.editing.remove_slot(pm_uid, slot_uid, dry_run=True)
if checked["status"] == "validated":
    removed = pme.editing.remove_slot(
        pm_uid, slot_uid, expected_version=checked["version"],
        expected=checked["expected"],
    )
    print(removed["status"], removed["after_rows"], removed["structure_changes"])

Add accepts a full saved snapshot for flat lists and layouts. Layout Remove also compares the full snapshot; flat Remove compares only the supplied target fields. Pass the query’s expected unchanged. A version alone cannot detect every raw edit. Snapshot mismatches return stale_popup for layouts, stale_snapshot for flat Add, or stale_slot for flat Remove. Missing fields in a full snapshot are not filled in automatically.

Add/Remove queries return validated or rejected with committed=False. They do not allocate UIDs, change saved values or versions, run editor hooks, or refresh the editor. Add queries have slots=[]; Remove queries show the same target before and after. Their expected can be passed to the same operation without dry_run=True. They do not predict final labels, cleanup, or hook success.

A rejected flat-list operation can leave editor callback changes reported in side_effects; this is not a promise to roll back every callback. A refresh exception can happen after the membership change committed. Preserve its traceback and reread the menu before retrying. Layout operations report saved-state restoration through restored_failure or unknown, as described above. These functions do not save Preferences to disk or provide Blender Undo.

Interpret the result¶

Slots are saved independently, in the mapping’s order. The batch is not atomic: the first rejected save stops later slots, while earlier commits remain. Inspect these fields before retrying:

Each attempted slot’s uid, status, before, after, reports, and diagnostics when present

A slot’s status is committed, rejected, or unchanged. An unexpected exception keeps its traceback and adds the already-committed UIDs; inspect the affected menu before repeating the operation. Syntax diagnostics identify the edit field and location without stripping or reindenting the source.

Invalid request types, fields, or values can raise TypeError / ValueError during preflight. Exceptions from an editor or callback can also use those types after saving has started. Do not infer “nothing changed” from the exception class: preserve its traceback and notes, and reread the target before retrying.

Readback verifies the saved definition. Check display and actions in the intended editor and mode separately. For the example above, successful Knife selection changes the active tool; it does not cut geometry by itself.

Update Context Router branches¶

For a Router, read_pm() also returns router, containing logic, digest, and diagnostics. Pass that digest to update_router() to check that its saved definition still matches the one read.

router["logic"] is a dictionary with branches (an ordered list) and otherwise. Each branch contains branch_uid, name, enabled, combine_mode, conditions, and target. Each condition contains its condition_uid and saved inputs such as source, op, value, and value_type.

Use move_router_branch() with exactly one of before_uid / after_uid to change priority, or remove_router_branch() to delete a branch. Both identify branches within the specified Router and preserve the remaining branch contents, condition UIDs, and Otherwise. They do not change the selected menu or its draft. The normal Branch menu’s Move Up, Move Down, and Remove Branch use the same operation rules, retaining the UI’s existing saved-value normalization.

snapshot = pme.editing.read_pm(router_uid)["router"]
branches = snapshot["logic"]["branches"]  # Inspect names and UIDs first.
result = pme.editing.move_router_branch(
    router_uid, branches[-1]["branch_uid"], before_uid=branches[0]["branch_uid"],
    expected_digest=snapshot["digest"],
)
print(result["status"], result["diagnostics"])

Read again before another edit and use the new digest. Moving to the current position, including a self anchor, returns unchanged without writing. dry_run=True returns validated with candidate and no after, even for an unchanged move. Other statuses follow update_router: committed, rejected, or unknown; read back before retrying an unknown result. Neither operation runs targets, saves Preferences to disk, or provides Undo.

Create a Router with mode ID ROUTER. To leave an unmatched shortcut to Blender’s normal handling, set Otherwise to Pass Through with {"pass": True}:

created = pme.create_pm(pme.PmCreationSpec("ROUTER", name="Mode Router"))
if not created.accepted:
    raise RuntimeError(created.diagnostics)
router_uid = created.pm_uid
before = pme.editing.read_pm(router_uid)["router"]
result = pme.editing.update_router(
    router_uid, otherwise={"pass": True}, expected_digest=before["digest"],
)
print(result["status"], result["diagnostics"])

Pass Through is meaningful for the invocation route: test the original shortcut’s behavior when no branch matches. For an existing Router, use its observed UID instead of creating another menu.

Each entry in branches updates the branch identified by branch_uid. Omit branch_uid to append a new branch. Unmentioned branches and fields stay unchanged. Supplying conditions replaces that branch’s entire condition list: include existing condition_uid values for rows that should retain their identity. New branches and conditions receive UIDs when omitted.

This example adds a branch for Mesh Edit Mode in the 3D Viewport to a known router_uid, calling the menu identified by target_uid:

def enum_condition(*attributes, value):
    return {
        "source": {
            "kind": "rna_path", "root": "context",
            "segments": [{"kind": "attr", "name": part} for part in attributes],
            "detected_type": "enum", "readonly": True, "owner_type": None,
        },
        "op": "equals", "value": value, "value_type": "enum",
    }

before = pme.editing.read_pm(router_uid)["router"]
result = pme.editing.update_router(
    router_uid,
    branches=[{
        "name": "Edit Mesh", "combine_mode": "all",
        "conditions": [enum_condition("area", "type", value="VIEW_3D"),

                   "fallback_name": "Mesh Tools"},

    expected_digest=before["digest"],
)
print(result["status"], result["diagnostics"])

from copy import deepcopy

The copied list retains the other conditions and every existing condition_uid. The update replaces this branch’s condition list; passing only the changed row would remove the omitted conditions. Branch fields not supplied, including its target and position, remain unchanged.

An active Mesh is not necessarily a selected Mesh. An active_object.type condition alone does not implement a selected-only requirement. That check can use an existing Property Getter such as return C.active_object is not None and C.active_object.select_get(), referenced by a pm_property_ref condition. This editing API does not create or edit Property callbacks; the Router recipe alone does not complete that selected-only requirement.

Omitting otherwise retains its current setting; a supplied dictionary updates only its specified fields. New branches default to enabled, combine_mode="all", and no conditions or target. An empty ordinary branch is not an unconditional match. Branch order remains significant: the first match wins.

The result contains status, candidate, before, after, dry_run, and diagnostics. Add dry_run=True to validate the requested changes without saving: status="validated" returns the candidate logic with after=None. It does not evaluate conditions or execute targets. Normal saves return committed, rejected, or unknown; before/after contain logic and digest when available. On unknown or a readback failure, read again before retrying. To save a Router preview, repeat the original branches / otherwise inputs and digest with dry_run=False. Preview UIDs are provisional; do not resubmit the candidate’s newly allocated branch UIDs as if they already existed.

An unresolved menu target produces router_target_menu_unresolved as a warning with its target UID and branch/Otherwise address; it does not prevent saving. Decoder diagnostics can also carry branch and row addresses. Check diagnostics even after validation or commit. Invoke the saved Router in matching and nonmatching contexts separately; authoring does not prove branch execution.

Edit one Property Stack condition¶

The row operations use the same authoring and save operations as the normal Property Stack editor. Add appends an enabled, incomplete row and returns its condition_uid; it does not create a SET entry until a definition is authored. Update accepts a fields dictionary with source, op, value, value_type, label, and/or enabled. Omitted fields are retained, and authoring_state is derived by the editor’s existing rules. The UID cannot be changed.

before = pme.editing.read_pm(stack_uid)["property_stack"]
added = pme.editing.add_property_stack_row(stack_uid,
    expected_digest=before["digest"])
if added["status"] != "committed":
    raise RuntimeError(added)
row_uid = added["condition_uid"]
updated = pme.editing.update_property_stack_row(stack_uid, row_uid, {
    "source": {"kind": "rna_path", "root": "context", "detected_type": "int",
               "readonly": False, "segments": [
                   {"kind": "attr", "name": "scene"},
                   {"kind": "attr", "name": "frame_current"}]},
    "op": "equals", "value": 1, "value_type": "int", "label": "First frame",
}, expected_digest=added["after"]["digest"])

Definition updates also create or update the corresponding derived SET entry. Label-only changes leave the write plan intact; enabled changes follow the editor’s existing SET rules. Independent writes, other rows, combine mode, false policy, HUD settings, and Property IDs are retained. No Getter or Setter is executed by these authoring calls.

An explicit source-only definition has op, value, and value_type set to None; it remains incomplete and removes its derived SET entry. An empty row can have its label/enabled state edited, but a definition update requires a non-null source. To remove an observed row, including the last one:

current = pme.editing.read_pm(stack_uid)["property_stack"]
removed = pme.editing.remove_property_stack_row(stack_uid, row_uid,
    expected_digest=current["digest"])

Removal also removes that row’s derived SET entry. These calls return the same before, after, candidate, diagnostics, and status fields as update_property_stack, plus condition_uid. A dry run returns validated without writing; its added UID is only a candidate until committed. A same-value update returns unchanged without saving. Unknown or ambiguous row UIDs, stale digests, and invalid fields are rejected. If reading existing storage repaired meaning or identity, row operations reject the implicit repair; inspect the diagnostics and use an explicit full-logic replacement if that repair is wanted. Read back after an unknown result or an exception before retrying. Preferences disk saving and Blender Undo are separate from these calls.

Author a Property Stack and show its state¶

For mode CONDITION, read_pm() includes property_stack: logic, digest, property_id (saved ID), registered_property_id (currently registered ID), diagnostics, and the separate while_true_hud settings. Reading does not evaluate Getter or run Setter. Use the registered ID for a widget; do not derive it from the menu name or assume registration succeeded. If saved logic cannot be decoded, logic is None; inspect its diagnostics before editing rather than rebuilding the stack from an empty definition.

update_property_stack() replaces the complete existing PropertyStackLogic shape: version, combine_mode, predicate_rows, and write_plan. It does not change Property IDs or HUD settings; putting HUD fields inside logic is rejected. For a new stack, the small local helper below describes two Boolean settings. TRUE selects Surface (Connected on, Projected off); FALSE writes nothing:

created = pme.create_pm(pme.PmCreationSpec("CONDITION", name="Surface"))
if not created.accepted:
    raise RuntimeError(created.diagnostics)
stack_uid = created.pm_uid
before = pme.editing.read_pm(stack_uid)["property_stack"]

def fixed_bool(uid, property_name, value):
    source = {"kind": "rna_path", "root": "context", "detected_type": "bool",
              "readonly": False, "segments": [{"kind": "attr", "name": part}
              for part in ("scene", "tool_settings", property_name)]}
    row = {"condition_uid": uid, "enabled": True, "authoring_state": "complete",
           "label": property_name, "source": source,
           "op": "is_true" if value else "is_false", "value": None, "value_type": "bool"}
    entry = {"entry_uid": "set_" + uid, "kind": "derived", "status": "manual_resolved",
             "derived_from_condition_uid": uid, "source": source,
             "value": value, "value_type": "bool", "custom_set_body": "",
             "enum_set_write_mode": None, "enum_set_write_values": []}
    return row, entry

pairs = [fixed_bool("connected", "use_proportional_connected", True),
         fixed_bool("projected", "use_proportional_projected", False)]

Check a script reference¶

When a slot uses a file inside a registered folder, save its path relative to that folder, such as scripts/.... The resolved absolute path identifies the file observed now. This example only builds a command string; it neither executes the script nor edits a slot.

import pme

reference = "scripts/modeling/align.py"
result = pme.resources.resolve_script(reference)

if result.status == "resolved":
    command = f"execute_script({reference!r})"
    print(command)  # execute_script('scripts/modeling/align.py')
else:
    print(result.status, result.candidates)

ScriptResolution contains reference, status, resolved_path, and candidates. resolved_path is an absolute path only on success, and None otherwise. candidates is a tuple of confirmed matching file paths.

status

Meaning

resolved

One unambiguous file was found; read permission and Python syntax have not been validated

missing

No matching file was found

ambiguous

Multiple distinct files match

unavailable

A required location could not be resolved or inspected, so resolution could not be completed

A relative reference checks every registered folder using the same resolver as script execution. Distinct user files are separate candidates even when their contents match. Aliases of the same real file are one candidate. The add-on package is considered only when no user candidate exists and user locations could be checked. Absolute references are also accepted.

Scan scope and updates¶

  • Scripts: Recursively scans lowercase .py files anywhere in the registered folder, skipping hidden folders and __pycache__. Directory symlinks are followed; each real directory is visited once per registered folder.

  • Icons: Lists lowercase .png files directly in each registered icon folder, excluding the reserved _intr_ prefix. relative_path is the file name. Use pme.resources.list_icon_folders() for the icon folders themselves; they have no display name. Conflicting files and names starting with _, which are hidden in the Custom picker, are included. This is not a list of icons confirmed to be selectable or drawable.

  • Settings and files: Uses the active resource configuration and inspects files on each call. Settings-file changes made in an external editor are loaded on the next startup or re-enable.

These functions do not execute scripts, decode images, create directories, or migrate settings. Files can change after a query; script execution resolves the reference again. Slot-usage analysis and automatic reference updates after moving or renaming files are outside this API’s scope.

When no resource folders are configured, list_folders(), list_icon_folders(), and list_files() return empty results without creating a default folder. These two functions raise RuntimeError if settings cannot be read and no previous valid configuration is available. list_files() raises ValueError for an unsupported kind.

User properties¶

User properties created with the Property Editor use the same access forms in PME commands (props()) and through import pme (pme.props()).

import pme

# Get the PropertyGroup and access a property as an attribute
pme.props().MyCounter = 10
value = pme.props().MyCounter

# Read or write by registered storage ID
value = pme.props("MyCounter")
written = pme.props("MyCounter", 10)

pme.props(name, None) remains a read operation; it does not write None. Named access is limited to properties registered by PME. An unregistered name returns None when read and False when written; it is not created as scratch storage. Code that used pme.props.MyCounter in earlier Experimental builds must use pme.props().MyCounter instead.

Runtime add-on identity¶

Use pme.ADDON_ID when a Blender API requires the current add-on module ID. The value follows the active package identity, including the bl_ext.<repository>.<package> identity used by Blender Extensions.

import bpy
import pme

addon_preferences = bpy.context.preferences.addons[pme.ADDON_ID].preferences

Use pme.preferences when only the PME preferences object is needed. Do not hard-code "pie_menu_editor" in new scripts.

Backward compatibility¶

PME1’s pme.context and the props() command global remain available. Existing props() scripts inside PME command slots continue to work.

# These still work in PME2
pme.context.open_menu("My Menu")
pme.context.event.mouse_x
pme.context.add_global("my_var", value)
props("MyCounter", 10)

Prefer pme.execute() and pme.invoke_pm() for new code.

Note

The public API is currently Experimental. The basic interface is intended to stay stable, but smaller details may change in future versions.
