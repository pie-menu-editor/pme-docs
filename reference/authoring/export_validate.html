Export and validation¶

export_menus() writes menus as PME’s JSON document. The validation functions check a document against the bundled JSON Schema v2 and PME’s UID rules, without changing or running it.

Function

Purpose

export_menus()

Exports menus as a JSON document, optionally to a file.

validate_json()

Validates a JSON string. Returns ValidationResult.

pme.validation.validate()

Validates already-parsed JSON data.

pme.validation.validate_file()

Validates a UTF-8 JSON file.

validate_uid()

Checks the format of a menu UID. Described in Execution, user properties and identity.

Export¶

pme.export_menus(pm_uids=None, *, include_referenced_menus=True, export_tags=True, filepath=None)¶

Export menus as PME’s JSON document.

The exporter and file writer are those of the Export Menus dialog. The selected menu, Select Mode and the list filters are neither read nor changed.

Parameters:

  • pm_uids (iterable of str or None) – UIDs of the menus to export, as a non-string iterable. None exports every menu.

  • include_referenced_menus (bool) – Also export the menus that the named menus refer to. See Referenced menus. No effect when pm_uids is None.

  • export_tags (bool) – Include tag names, tag UIDs and the tag registry.

  • filepath (str or None) – File to write the JSON text to. .json is appended when the path does not end in .json (case-sensitive). An existing file is replaced.

Returns:

The result described below.

Return type:

dict

Raises:

  • TypeError – pm_uids is a string, bytes or not iterable; include_referenced_menus or export_tags is not a bool; or filepath is not a non-empty string.

  • ValueError – pm_uids is empty, a UID in it is rejected, or the data cannot be exported. See Errors.

  • RuntimeError – Called off Blender’s main thread ("Menu export requires Blender's main thread"), while PME runs its startup scripts ("Menu export requires PME to finish loading"), or while preferences is None ("PME preferences are unavailable").

  • KeyError – ADDON_ID is not in bpy.context.preferences.addons, as for preferences.

  • OSError – The file cannot be written, for example FileNotFoundError when its directory does not exist.

Result

Key

Type

Value

data

dict

The document. See Exported document.

text

str

The exact JSON text of data, as written to the file.

pm_uids

list[str]

UIDs of the exported menus, in document order.

warnings

list[str]

Problems that did not stop the export. See Warnings.

filepath

str or None

The path of the written file, including an appended .json. None when filepath was not given.

Errors

Every error is a ValueError. The pm_uids checks run in the given order and name the first UID that fails.

Message

Cause

pm_uids must name at least one menu; pass None to export all

pm_uids is empty.

Menu UID is invalid: <uid>

Not a menu UID in the format validate_uid() accepts. The UID is shown with repr().

Menu UID is listed more than once in pm_uids: <uid>

The UID appears twice in pm_uids.

Menu UID is missing: <uid>

No saved menu has the UID.

Menu UID is ambiguous: <n> saved menus share <uid>

Several saved menus have the UID.

PME: Context Router logic export failed for menu '<name>': <source> refers to <target>, which is outside the exported menu set

A Context Router’s target menu is not exported. <source> is branch '<label>', otherwise '<label>' or condition '<label>'. <target> is menu '<current name>', or a menu that is not in Preferences (UID <uid>).

PME: Context Router logic export failed for menu '<name>': <codes>

The Context Router’s saved logic cannot be read or exported.

PME: <mode> export requires at most <n> slots: <name>

A menu type with a fixed number of slots has more slots.

PME: Export blocked by invalid menu identity (<reason>, count=<n>)

The saved menus fail PME’s menu identity check, such as a missing, invalid or duplicated menu UID. <reason> names the check.

A tag registry code, such as tag_registry_export_plan_failed

The tag registry cannot be exported.

The data errors (Context Router and slot count) are ExportDataError. An error raised after warnings were collected is an ExportError whose warnings attribute holds them. Both classes subclass ValueError and are not exported by pme; read the warnings with getattr(error, "warnings", ()).

Warnings

Message

Cause

PME: <n> Command/Custom slot(s) call menus that could not be resolved, so those menus were not included: <slots>

A Command or Custom slot calls a menu that cannot be identified. Reason per slot: menu not found, duplicate menu name or target not static.

PME: <n> Command/Custom slot(s) reference properties that could not be resolved, so those properties were not included: <slots>

A props() reference in a Command or Custom slot cannot be identified. Reason per slot: prop id not found, display name ambiguous or target not static.

PME: Property Stack logic omitted for menu '<name>': <codes>

The saved logic cannot be read. The menu is exported without it.

PME: Property Stack logic repaired for menu '<name>': <codes>

The saved logic was read after normalization.

<slots> lists up to 10 slots as '<menu>' slot <position> '<slot name>' (<reasons>), then and <n> more. The two slot warnings are produced only with pm_uids and include_referenced_menus=True.

Example

result = pme.export_menus([pm_uid], filepath="C:/exports/shading_pie")
print(result["filepath"], result["pm_uids"], result["warnings"])

Notes

  • A Context Router’s target is exported when include_referenced_menus is True or when its UID is in pm_uids; then the “outside the exported menu set” error does not occur for it.

  • Before the export, a slot of an exported menu whose slot UID is missing, invalid or used twice in that menu receives a new UID. The new UID is kept in the saved menu.

  • Menus are written in the order of the menu list, not in the order of pm_uids. The developer option Sort Exported Menus by Name sorts them by name.

Exported document¶

The document follows JSON Schema v2. Hotkeys of the exported menus are part of it. Script files that slots call are not; a recipient needs them as separate files.

Key

Value

$schema

"https://docs.pie-menu-editor.com/schema/pme2-2.0.json"

schema_version

"2.0"

addon_version

PME version, such as "2.3.1".

exported_at

UTC time of the export, such as "2026-11-18T06:59:46Z".

menus

One object per menu: uid, name, mode, enabled, hotkey, settings, items, and as applicable tags, extensions (Property Stack and Context Router logic, tag UIDs), description, description_is_expr and poll.

extensions

pme.exported_with.blender_version, pme.requires (features the document uses, and a minimum Blender version when one applies) and pme.tag_registry.

tags

All tag names used by the exported menus, when export_tags is True and there are any.

hotkey holds key, ctrl, shift, alt, oskey, any, key_mod, chord, keymaps, activation and drag_direction, plus repeat and tweak_direction when set.

Referenced menus¶

With pm_uids and include_referenced_menus=True, the exported set is the named menus plus every menu they reach, repeated until nothing is added:

  • Menu slots, including disabled slots.

  • Property Stack and Context Router references to other menus.

  • Menu calls and props() references in the text of Command and Custom slots, when they resolve to one menu by UID or by a name that only one menu has.

A reference that cannot be resolved adds nothing; Command and Custom slot references of that kind are listed in warnings. With include_referenced_menus=False, only the named menus are exported.

Validation¶

valid=True means that the requested checks passed. It does not guarantee that an import succeeds in the current Blender setup or that the stored commands run.

Validation stages¶

  1. Text (validate_json() only). An empty or whitespace-only string, or None, gives E102. Text that is not JSON gives E101.

  2. Root. An empty or false value ({}, [], "", 0, null) gives E102. An object with $schema or schema_version is checked as Schema v2 (stages 3 to 5). A list, or an object with a menus list and a version string of dot-separated integers such as "1.18.7", is a PME1 document: the result has warning W301 and no further check runs. Anything else gives E206.

  3. Schema. The document is checked against the bundled schema pme2-2.0.json. One failure is reported per call. When the failure is a missing required field, each missing field of that object is an issue with the same message. Failures of type and required fields are reported before failures of conditional rules. The next failure appears after the first is fixed.

  4. UIDs. Runs when the schema check passes. Menu UIDs must be valid and match the menu’s mode, and must be unique in the document. Slot UIDs must be valid and unique within their menu. Several issues can be reported.

  5. References. Runs after the UID stage when check_references is True. Several issues can be reported.

    • A Menu slot whose target is a menu UID must find that UID in the same document. A target given as a name is not checked.

    • The logic of a Property Stack (CONDITION) or Context Router (ROUTER) is decoded, and the menu UIDs it depends on must be in the same document. A CONDITION without logic is skipped.

With strict=True, a result with any warning has valid=False. The warnings stay in warnings.

pme.validate_json(json_string, *, strict=False, check_references=True)¶

Validate a PME JSON document given as text.

The same function is pme.validation.validate_json. The document is read only: it is not changed, its Python code is not run, and its $schema URL is not downloaded.

Parameters:

  • json_string (str, bytes, bytearray or None) – The JSON text. bytes and bytearray are read as json.loads() reads them. None counts as empty text.

  • strict (bool) – Make any warning invalidate the result.

  • check_references (bool) – Run the reference stage. False skips it; the schema and UID stages still run.

Returns:

The issues found and the document’s metadata.

Return type:

ValidationResult

Raises:

TypeError – json_string is of another type, such as an int or an already-parsed dict. The message names the type, for example "json_string must be str, bytes, bytearray or None, not dict". Validate parsed data with pme.validation.validate().

Example

result = pme.validate_json(pme.export_menus([pm_uid])["text"])
if not result.valid:
    print(result.format_report())

Notes

  • Problems in the document are returned as issues, not raised.

  • check_references=False fits a document whose target menus are supplied in another document, such as part of an export.

  • Legacy name references and Blender menu type names are not resolved against the running Blender session.

  • W301 means that the item contents and name references of the PME1 document have not been validated against Schema v2. Import has its own checks.

  • The Extension bundles fastjsonschema 2.22.2. Blender can already have loaded its own 2.21 in the same Python process, so the version in use can differ. Validation uses their shared API and does not replace the loaded library.

pme.validation.validate(data, *, strict=False, check_references=True)¶

Validate already-parsed JSON data.

Starts at the Root stage. data is not changed.

Parameters:

  • data (object) – A parsed JSON value, such as the result of json.loads().

  • strict (bool) – Make any warning invalidate the result.

  • check_references (bool) – Run the reference stage.

Returns:

The issues found and the document’s metadata.

Return type:

ValidationResult

pme.validation.validate_file(filepath, *, strict=False, check_references=True)¶

Read a UTF-8 JSON file and validate its text as pme.validate_json() does.

Parameters:

  • filepath (str) – Path of the file.

  • strict (bool) – Make any warning invalidate the result.

  • check_references (bool) – Run the reference stage.

Returns:

The issues found and the document’s metadata.

Return type:

ValidationResult

Notes

  • A file that cannot be read gives E101 with the message "File not found: <path>", "Permission denied: <path>" or "Failed to read file: <error>". A file that is not UTF-8 gives the last form. Nothing is raised.
