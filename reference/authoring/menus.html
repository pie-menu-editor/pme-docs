Menus¶

Whole-menu operations: create, find, list and invoke menus (pme); read a menu’s saved definition, change its name, description, Poll, enabled state and tags, duplicate and delete menus, and find what refers to a menu (pme.editing). Slots, layout rows, type settings, hotkeys and the definitions of Properties, Property Stacks and Context Routers have their own pages. Exporting menus is export_menus() on Export and validation.

Function

Purpose

create_pm()

Creates a menu with the default contents of its type.

find_pm()

Returns a handle to one menu, found by UID or name.

list_pms()

Returns handles to all menus, optionally filtered.

list_tags()

Returns the tag names that menus use.

invoke_pm()

Requests that a menu opens.

read_pm()

Returns a menu’s saved definition.

update_pm()

Changes the name, description, description format and Poll.

set_enabled()

Enables or disables menus.

update_tags()

Adds and removes tag names on menus.

duplicate_pm()

Copies a menu.

delete_pms()

Deletes menus.

find_references()

Lists the saved places that refer to menus.

Calling rules¶

  • Menus are addressed by UID. A name can change; find a menu by name with find_pm() and keep its UID for later calls.

  • Every pme.editing function on this page raises RuntimeError when it is called off Blender’s main thread, before PME has finished loading, or when PME’s Preferences are unavailable.

  • No function on this page saves Preferences to disk or adds a Blender Undo step. Only invoke_pm() opens a menu; no function runs a menu’s actions.

  • status values are defined on Results and guards. General rules for editing are on Concepts.

Menu type identifiers¶

The identifier is the mode_id of PmCreationSpec, the mode of PMHandle and read_pm()["mode"]. A menu UID starts with its type’s prefix and _, for example pm_a2b3c4d5. Hotkey tells whether the type has a hotkey. editable_slots is the value read_pm() returns: False types are edited with their own operations, not the slot operations.

Finding and invoking menus¶

pme.find_pm(name=None, *, uid=None)¶

Return a handle to one menu, found by UID or by exact name.

Parameters:

  • name (str or None) – Exact menu name. Used only when uid is not given.

  • uid (str or None) – Menu UID. When given, name is ignored.

Returns:

A handle, or None when no menu matches.

Return type:

PMHandle or None

Example

handle = pme.find_pm("Mesh Tools")
if handle:
    pm_uid = handle.uid

Notes

  • A UID that is not found returns None. The name is not tried.

  • A UID search returns the first menu with that UID. It does not detect a UID shared by several menus.

  • Returns None when PME’s Preferences are unavailable or pending Tag changes cannot be applied.

  • The handle is a copy taken at the call. It does not follow later changes.

pme.list_pms(mode=None, *, enabled_only=False)¶

Return handles to all menus in collection order.

Parameters:

  • mode (str or None) – A menu type identifier (Menu type identifiers). Only menus of that type are returned. None returns all types. An unknown identifier returns [].

  • enabled_only (bool) – Return only enabled menus.

Returns:

One handle per menu. [] when PME’s Preferences are unavailable or pending Tag changes cannot be applied.

Return type:

list[PMHandle]

Example

for handle in pme.list_pms(mode="PMENU", enabled_only=True):
    print(handle.uid, handle.name, handle.tag)
pme.list_tags()¶

Return the tag names that menus use.

Returns:

Each used tag name once: in Tag Registry order when the registry is active, otherwise sorted by exact case. Untagged is not included. [] when PME’s Preferences are unavailable or pending Tag changes cannot be applied.

Return type:

list[str]

Example

>>> pme.list_tags()
['Modeling', 'Sculpt', 'UV']
pme.invoke_pm(pm_or_name=None, *, name=None, uid=None)¶

Request that a menu opens, as its hotkey does.

True means the request was sent without an error. It does not confirm that the menu was displayed or that an action ran.

Parameters:

  • pm_or_name (PMHandle, str or None) – A handle or a menu name. Takes precedence over name and uid. A handle is resolved by its uid, so it opens the same menu after the menu or another menu is renamed. A handle with an empty uid is resolved by its name.

  • name (str or None) – Menu name. Used when pm_or_name and uid are not given.

  • uid (str or None) – Menu UID. Used when pm_or_name is not given. Takes precedence over name.

Returns:

Whether the request was sent.

Return type:

bool

Example

opened = pme.invoke_pm(uid=pm_uid)

Notes

Returns False without raising when:

  • no menu matches;

  • the menu is disabled;

  • the menu’s Poll or the current context does not allow it;

  • the call to Blender’s operator raises;

  • PME is running its startup scripts (scripts/autorun/, scripts/register/).

class pme.types.PMHandle(name, mode=None, enabled=True, uid='', tag='')¶

A copy of one menu’s identity, returned by find_pm() and list_pms(). Changing its fields changes nothing in PME. The class is pme.types.PMHandle; it is not available as pme.PMHandle.

name: str¶

Menu name.

mode: str or None¶

Menu type identifier (Menu type identifiers).

enabled: bool¶

Whether the menu is enabled.

uid: str¶

Menu UID.

tag: str¶

The saved tag text: names separated by commas, for example "Modeling, Sculpt". Empty when the menu has no tag.

Creating menus¶

pme.create_pm(spec, *, request_refresh=None)¶

Create a menu with the default contents of its type.

The menu is created as New in the editor creates it. Its slots and settings are edited afterwards: slots with update_slots(), type settings with update_settings(), a Property with update_property().

Parameters:

  • spec (PmCreationSpec) – The menu to create. slots must be empty and data must be None.

  • request_refresh (callable or None) – Called once with the argument "global" after the menu is created and the Tree is updated, to redraw the editor. None requests no redraw.

Returns:

The UID of the new menu, or the rejection codes.

Return type:

PmCreationResult

Diagnostics

diagnostics of the result holds codes, not dictionaries. The checks run in the order of the table. The spec checks report every failing code together. Later checks run only when the earlier ones pass. Every code except refresh_failed means that no menu was created.

Code

Cause

spec_shape_invalid

spec is not a PmCreationSpec, or a field has the wrong type: mode_id or name is not a str, data is not a str or None, slots is not a tuple or list, or a slot field is not a str. Reported alone.

unknown_mode

mode_id is not in Menu type identifiers.

logic_envelope_mode_unsupported

CONDITION or ROUTER with slots or data.

slot_count_exceeds_fixed

More slots than the type’s fixed count (PMENU and VMENU 10, STICKY 2, CONDITION and ROUTER 0).

slot_count_below_fixed

STICKY with one slot. PMENU and VMENU accept fewer slots.

data_marker_mismatch

The part of data before ? is not the type’s data marker.

data_query_malformed

A pair after ? in data is not key=value.

unknown_slot_mode

A slot’s mode is not EMPTY, COMMAND, PROP, MENU, HOTKEY, CUSTOM, INVOKE, FINISH, CANCEL or UPDATE.

slots_unsupported_by_create_pm

slots is not empty.

data_unsupported_by_create_pm

data is not None.

boot_worker_thread_unsupported

Called off Blender’s main thread while PME runs its startup scripts.

boot_refresh_callback_unsupported

request_refresh given while PME runs its startup scripts.

route_pm_identity_*

The saved menus fail the UID check, for example route_pm_identity_uid_duplicate when several menus share a UID.

route_target_rejected

The creation target could not be prepared.

route_dry_run_rejected

The menu collection changed, or the new UID collided, between preparation and writing.

route_apply_failed

Creating the menu raised. The added entry was removed again. The original exception is printed to Blender’s console.

route_receipt_invalid

The creation step returned no valid result.

refresh_failed

Not a rejection: accepted is True. The menu was created, but the Tree update or request_refresh raised. The exception is printed to Blender’s console.

Example

created = pme.create_pm(pme.PmCreationSpec(mode_id="VMENU", name="Mesh Tools"))
print(created.accepted, created.pm_uid, created.diagnostics)
if created.accepted:
    menu = pme.editing.read_pm(created.pm_uid)

Notes

  • accepted=True means the menu exists in Preferences. It does not mean that Preferences were saved to disk, that the menu was invoked, or that it is available at run time immediately.

  • After refresh_failed, read the returned UID instead of creating the menu again.

  • Placement, Auto Tag and keymap inheritance follow New in the editor with the current list state. The new menu becomes the active menu.

  • An empty name uses the type’s default name. A name that is in use receives a suffix such as .001.

  • A request rejected before the route_* checks does not read or change Preferences.

  • From a startup script on the main thread, only the saved menu is created: no hotkey or editor registration and no display refresh run in the call.

Reading a menu¶

  • A slot’s text is the stored text. read_slot_inputs() returns the same slots under the input names that update_slots() accepts.

Name, description and Poll¶

pme.editing.update_pm(pm_uid, changes, *, expected=None)¶

Change a menu’s name, description, description format or Poll source.

Fields are saved one at a time; the call is not atomic. The first rejected field stops the sequence. Fields saved before it stay saved.

Parameters:

  • pm_uid (str) – UID of the menu.

  • changes (dict) – Field name mapped to its new value. Accepted names: name, description, description_is_expr, poll_cmd. Fields that are not named keep their values.

  • expected (dict or None) – Field name mapped to the value it must have now. Any subset of the four fields. On a mismatch nothing is written (stale_metadata).

Returns:

The result described below.

Return type:

dict

Raises:

  • TypeError – changes or expected is not a mapping, description_is_expr is not a bool, or another value is not a str.

  • ValueError – A field name is not one of the four, a string contains a NUL character or text that cannot be encoded as UTF-8, or the UID is missing, invalid or ambiguous.

Result

Key

Type

Value

status

str

See Status below.

committed

bool

True only when status is "committed".

pm_uid

str

The pm_uid argument.

before

dict

The four fields read before the call.

after

dict

The four fields read after the call.

changed_fields

list[str]

Fields whose value differs between before and after, including changes made by editor callbacks.

fields

list[dict]

One entry per attempted field, in save order: field, status (committed, unchanged or rejected), before, after and diagnostics.

pending

list[str]

Fields that were not attempted.

side_effects

list[dict]

Present only when name is in changes and a slot of any menu changed. One entry per slot: pm_uid, pmi_uid, before, after.

diagnostics

list[dict]

The diagnostics of all fields, or the stale_metadata entry.

Status

status

Meaning

committed

At least one field was saved and none was rejected. Other fields can be unchanged.

unchanged

Every field already had the requested value, or changes is empty. Nothing was written.

partial

A field was rejected after an earlier field or a callback changed saved values. Inspect fields, pending, before/after and side_effects before retrying.

rejected

Nothing changed: expected did not match, or a field was rejected before any value changed.

Diagnostics

code

Cause, and extra keys

stale_metadata

A value in expected differs from the saved value. fields lists the names.

rename_rejected

The editor kept the old name for a different, non-empty name.

name_adjusted

The saved name differs from the requested one: @ was removed, or a suffix such as .001 was added because the name is in use. requested and actual give both names.

metadata_value_not_retained

A setter did not keep the requested description, description_is_expr or poll_cmd.

poll_compile_error

poll_cmd was saved but does not compile. message gives the error. The field status is not changed by this diagnostic.

Example

Add a plain-text menu description, checking that the four fields are unchanged since they were read:

before = pme.editing.read_pm(pm_uid)
fields = ("name", "description", "description_is_expr", "poll_cmd")
result = pme.editing.update_pm(pm_uid, {
    "description_is_expr": False,
    "description": "Mesh tools. Unmatched contexts keep Blender's shortcut.",
}, expected={key: before[key] for key in fields})
print(result["status"], result["after"], result["diagnostics"])

Notes

  • When both description and description_is_expr are given, description_is_expr is saved first, so the format conversion does not rewrite the supplied description. Other editor callbacks can also change saved values; they appear in changed_fields.

  • Renaming uses the editor’s rename: Menu slots that link the menu, Panel Group items named after a renamed Pop-up Dialog, the Tree and hotkey registration are updated. Command, Custom and Poll source text and a Router target’s fallback_name are not rewritten and not listed in side_effects; name-based calls in them keep the old name.

  • @ is removed from a requested name. An empty name, or the current name, leaves the name unchanged.

  • Renaming a Property Stack whose Property ID is not locked can generate a new ID. Read property_stack["registered_property_id"] again after renaming; widgets that embed the old ID are not rewritten.

  • poll_cmd is appended to def poll(cls, context):. A single-line body such as "return context.mode == 'EDIT_MESH'" is valid as it is. A multi-line body starts with a newline and indents its lines.

  • Poll source that does not compile is saved, as in the editor, with poll_compile_error. Slot cmd, prop and custom syntax errors are instead rejected before the slot is saved. Neither check proves run-time behavior.

  • Enabled state, hotkeys and type settings are not fields of this function. The Poll and description sources are not evaluated.

  • An unexpected exception keeps its traceback and gains a note naming the committed fields. Read the menu and the menus that refer to it before retrying.

Enabling and disabling¶

pme.editing.set_enabled(pm_uids, enabled, *, expected=None, dry_run=False)¶

Enable or disable menus, as the editor’s batch Enable and Disable do.

All targets are checked before the first write. If a write fails, the enabled values already written are restored.

Parameters:

  • pm_uids (non-string iterable of str) – Unique menu UIDs. Targets are processed in collection order. An empty iterable returns unchanged.

  • enabled (bool) – The value for every target.

  • expected (dict[str, bool] or None) – Each requested UID mapped to the saved value it must have now; exactly the requested UIDs. On a mismatch the call is rejected before writing. None uses the values read at the start of the call.

  • dry_run (bool) – Check and return without writing.

Returns:

The result described below.

Return type:

dict

Raises:

  • TypeError – enabled or dry_run is not a bool (an int is not accepted), pm_uids is a string, or expected is not a mapping of bools.

  • ValueError – pm_uids contains an invalid or duplicate UID, or expected does not name exactly the requested UIDs.

See Status below.

True only when status is "committed".

The dry_run argument.

Status

Meaning

Every value was written and read back.

Diagnostics

The rejection or failure entry has code (the reason) and rollback_reason.

code

Cause, and extra keys

pm_availability_target_missing

A UID is not in the menu collection.

pm_availability_live_identity_invalid

The saved menus fail the UID check, for example when several menus share a UID. The check covers the whole collection, not only the targets.

pm_availability_expected_mismatch

A value in expected differs from the saved value. before holds the saved values.

pm_availability_target_state_unavailable

A target’s enabled value could not be read.

pm_availability_collection_stale

The menu collection changed during the call. Also a rollback_reason.

pm_availability_target_stale

A target’s value changed before its write.

pm_availability_apply_failed

A setter raised.

pm_availability_apply_readback_mismatch

A setter did not keep the value.

pm_availability_post_apply_mismatch

The final read differs from the requested value.

pm_availability_rollback_incomplete

Only as rollback_reason: the restored values could not all be confirmed.

pm_availability_target_unavailable

After the call, a target could not be resolved. pm_uid, phase and reason (the resolver status).

pm_availability_readback_unavailable

Reading a target after the call raised. pm_uid, phase, exception_type.

pm_availability_registration_unavailable

Reading a target’s hotkey registration raised. pm_uid, phase, exception_type.

pm_availability_context_unavailable

Selection and visibility could not be read. phase (before or after), exception_type.

Example

preview = pme.editing.set_enabled([pm_uid], False, dry_run=True)
print(preview["status"], preview["before"], preview["planned_uids"])
if preview["status"] == "validated":
    result = pme.editing.set_enabled(
        [pm_uid], False, expected=preview["expected"],
    )
    print(result["status"], result["after"], result["registration"])
    print(result["diagnostics"])

Notes

  • committed confirms the saved enabled values only. registration reports the current hotkey state. It does not check Macro, Property, Property Stack or Panel resources, Poll, Getter or Setter, or whether actions run. A registration warning or unknown observation does not change a committed status.

  • A disabled menu, a menu without a key, a type without a hotkey and a Vector Menu with Open Mode CLICK require no hotkey registration (not_required).

  • After a dry run, registration is the current registration, not a prediction.

  • A dry run does not reserve the targets or prove that their callbacks will succeed. A later call resolves and checks again.

  • A restore covers enabled values only, not other saved fields or editor resources. After a failure, read before, after, attempted_uids, changed_uids, reason, rollback_reason and diagnostics together.

  • The selection, open drafts (also one owned by a target) and list filters stay as they are, even when a target becomes hidden. visibility is the last-rendered region’s evidence, can be unknown, and does not prove that a new frame has drawn.

Tags¶

pme.editing.update_tags(pm_uids, *, add=(), remove=(), expected=None, dry_run=False)¶

Add and remove tag names on several menus in one batch.

The call has two phases: the normal Tag synchronization, then the batch write that the editor’s tag operations use. They are not one atomic transaction.

Parameters:

  • pm_uids (non-string iterable of str) – Unique menu UIDs.

  • add (non-string iterable of str) – Names to add. Each is trimmed. A comma separates several names. An empty name and Untagged are ignored and listed in ignored_names.

  • remove (non-string iterable of str) – Exact names to remove. Not trimmed, not split at commas.

  • expected (dict or None) – The complete expected of an earlier result of this function, passed unchanged: activated, targets_digest and definitions_digest. It is compared before synchronization.

  • dry_run (bool) – Check and return without synchronizing or writing.

Returns:

The result described below.

Return type:

dict

Raises:

  • TypeError – dry_run is not a bool, pm_uids, add or remove is a string or contains a non-string, or expected["activated"] is not a bool.

  • ValueError – pm_uids contains an invalid or duplicate UID, a UID is missing or ambiguous, remove contains a name twice, a name occurs twice across add or in both add and remove, or expected is not a mapping with exactly the three keys or has a digest that is not a lowercase SHA-256 hex string.

targets = [first_pm_uid, second_pm_uid]

    targets, add=["Review"], remove=["Draft"], dry_run=True,
)

    result = pme.editing.update_tags(
        targets, add=["Review"], remove=["Draft"], expected=preview["expected"],
    )
    print(result["status"], result["after"], result["synchronized"])

Notes

  • The batch uses the editor’s tag writer, with the Tag Registry active or inactive. It does not delete tag definitions.

  • Names keep their case and Unicode. add=["A,B"], remove=["B"] is a conflict (ValueError). Ignored additions still take part in the duplicate checks. There is no additional name-length limit.

  • The write can normalize the order and duplicates of the saved tag text even when the set of names does not change, for example for an existing membership or a missing removal. Compare the saved values, not name sets.

  • expected survives a JSON round trip. It covers the targets’ saved tag text, references and projection stamps and the registry definitions. A stale expected is rejected without writing.

  • A dry run checks the inputs, the targets and the name transformation. It does not synchronize, allocate UIDs or predict new definitions, and does not prove that a later write succeeds.

  • Empty changes or an empty target set return unchanged after the expected check, without synchronization or refresh.

  • recovery.carrier_matches compares saved tag data with baseline: "before" when synchronization failed, "after_synchronize" when the batch write failed. True proves equality of saved data only. attempted is None because rollback execution is not known; a match is not reported as restored_failure.

  • A failed readback or refresh after a successful batch write does not change a committed result.

  • The active menu, the selected menus and the open draft stay as they are. The same Tree row stays selected when it is still available and the refresh succeeds. active_hidden_by_list_filter is the current mode, tag, new and health filter result, without name search and collapsed rows; None when unknown.

Duplicating¶

pme.editing.duplicate_pm(source_pm_uid, *, name=None, expected=None, dry_run=False)¶

Notes

  • The copy is placed after its source in collection order, whatever the active menu or the displayed sort order.

  • The copy and its slots receive new UIDs. Slot contents, slot enabled, tags and the editor’s type-specific copy behavior are kept. References in the copy keep their targets.

  • The fields in not_inherited are not copied: the copy starts enabled, without a hotkey key.

  • A Property Stack copy keeps the HUD appearance with monitoring off, and does not reuse the source’s Property ID.

  • A dry run creates no UID, initializes no version, changes no selection, registers nothing and writes no HUD settings. It does not reserve a name or fix the collection order.

  • expected survives a JSON round trip. It covers the source’s saved values, including edits that do not update a version, and the collection version.

  • The same Tree row stays selected when it still exists. A copy hidden by a filter does not cause another menu to be selected.

  • A failed refresh or readback does not undo a confirmed commit. recovery covers only the Duplicate’s own rollback and its saved-data checks, not editor registration or host resources.

A stale result needs a new read and a new decision. Without expected, the state at the start is still checked again before each target is removed.

  • references includes Router and Property Stack references that are disabled or incomplete. Python that builds a reference at run time is not found; coverage warnings do not prevent deletion.

  • An open draft of another menu stays intact. An active menu outside the targets keeps its UID. When the active menu is deleted, the next surviving menu after it becomes active, or else the nearest one before it. Filters are not cleared to show a surviving menu.

  • Recovery of saved data and recovery of host registration are separate: a restored definition does not prove that every editor resource was restored. A failed display refresh after the deletion keeps the committed result.

  • recovery.hotkey_observation covers the deletion checkpoint and PME’s own hotkey records only. An absent record does not prove that every Blender keymap item or other editor resource was removed.
