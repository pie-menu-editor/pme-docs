Property Stack¶

A Property Stack (menu type CONDITION) combines condition rows into one Boolean switch and writes settings when the switch is set. Its logic is replaced as a whole or edited one condition row at a time. The While True HUD has its own function; the logic functions leave it and the Property ID unchanged. A single Property is described on Property.

Function

Purpose

read_pm()

Returns the logic and registration under property_stack.

update_property_stack()

Replaces the complete logic.

add_property_stack_row()

Appends an empty condition row.

update_property_stack_row()

Changes one condition row.

remove_property_stack_row()

Removes one condition row and its derived write entry.

update_property_stack_hud()

Changes the While True HUD.

See also: Author a Property Stack and show its state, and the Property Stack Editor for the meaning of evaluation-only rows and write modes.

Reading a Property Stack¶

read_pm(pm_uid)["property_stack"] holds:

Key

Type

Value

logic

dict or None

The saved logic as the storage decoder reads it. See Logic. None when the saved logic cannot be decoded.

digest

str

Hex digest of the saved logic text. Pass it as expected_digest.

property_id

str

Saved Property ID.

registered_property_id

str

ID the Property Stack is currently registered under. Empty when it is not registered.

while_true_hud

dict

While True HUD settings. Changed with update_property_stack_hud(). See below.

diagnostics

list[dict]

Problems found while reading the saved logic, with scope "current_storage". See below.

 
>>> pme.editing.read_pm(stack_uid)["property_stack"]
{'logic': {'version': 1, 'combine_mode': 'all', 'predicate_rows': [],
           'write_plan': {'false_policy': 'no_op', 'entries': []}},
 'digest': 'e3b0c442...', 'property_id': 'surface',
 'registered_property_id': 'surface',
 'while_true_hud': {'enabled': False, 'message': '', 'is_expr': False,
                    'area_type': 'VIEW_3D', 'alignment': 'TOP',
                    'display': 'LABEL', 'icon': '', 'use_color': False,
                    'color': [1.0, 1.0, 1.0]},
 'diagnostics': []}

Reading does not evaluate the Getter or run the Setter. registered_property_id is the ID a widget uses, for example L.prop(props(), registered_property_id). It is not derived from the menu name.

while_true_hud has the keys of Schema v2 PropertyStackWhileTrueHud. The values of a new Property Stack are shown above. The fields are listed under While True HUD fields; the editor is described under While True HUD — notify while conditions match.

logic is the storage decoder’s normalized view, not the raw stored JSON. The view can omit unsupported or stale write entries, or turn writes off. property_stack_storage_normalized reports each difference. When logic is None, the row operations reject the stack and update_property_stack() replaces it.

Codes in diagnostics:

code

Cause, and extra keys

authoring_storage_invalid

The saved text is not JSON, or an integer value of a float row cannot become a float. logic is None.

authoring_storage_not_string

The saved value is not text. logic is None.

authoring_storage_non_object

The saved JSON is not an object. logic is None.

authoring_storage_unsupported_version

version is not 1. logic is None.

authoring_storage_write_entry_uid_duplicate

Two write entries share an entry_uid. logic is None.

authoring_storage_write_entry_enum_set_value_malformed

enum_set_write_values is not a list of non-empty strings. logic is None.

authoring_storage_write_entry_pm_property_fields_malformed

A write entry has target_uid or write_mode. logic is None.

authoring_storage_write_entry_source_malformed

A write entry’s PME Property or Property Stack source is not read-only. logic is None.

authoring_storage_write_entry_pm_property_ref_stale_dropped

A write to a PME Property has no matching condition row. The view omits it.

authoring_storage_write_entry_kind_unsupported

A write entry has an unknown kind. The view has no write entries.

property_stack_storage_normalized

The view differs from the saved JSON. path names the field, input the saved value and normalized the value in the view; input_present and normalized_present tell an added or removed field. normalization is "canonical" for the same meaning and "repair" otherwise.

Each entry has code, path, severity and scope. The decoder codes also have address (a position such as entry_index) and blocking (True when logic is None). severity is "error" for a blocking code and "warning" otherwise.

Functions¶

pme.editing.update_property_stack(pm_uid, *, logic, expected_digest=None, dry_run=False)¶

Replace the complete logic of a Property Stack.

Rows and write entries that logic omits are removed. UIDs are not allocated or repaired: each condition_uid and entry_uid must be present and unique.

Parameters:

  • pm_uid (str) – UID of the Property Stack.

  • logic (dict) – The complete logic, in the form described under Logic. Without while_true_hud; change the HUD with update_property_stack_hud().

  • expected_digest (str or None) – read_pm()["property_stack"]["digest"]. The update is rejected with stale_property_stack_digest when the saved logic has changed.

  • dry_run (bool) – Check the logic and return without writing.

Returns:

The result described under Common result. condition_uid is absent.

Return type:

dict

Raises:

RuntimeError – The call is not on Blender’s main thread, or PME has not finished loading.

Status

committed, validated, unchanged, rejected or unknown. Logic equal to the read logic returns unchanged without writing, on a new Property Stack too. When the read diagnostics have a "repair" normalization, the same logic is written instead: the write removes from the saved data what the read view leaves out.

Diagnostics

In addition to Common result. All have scope "input".

code

Cause, and extra keys

property_stack_logic_must_be_a_mapping

logic is not a dict.

property_stack_hud_not_editable

logic has while_true_hud.

property_stack_input_must_be_json_values

logic holds a value JSON cannot represent, such as a set or NaN.

property_stack_schema_invalid

logic does not match Schema v2 PropertyStackLogic. path names the field and message the rule.

schema_v2_logic_condition_uid_repaired

A condition_uid repeats an earlier one.

schema_v2_logic_entry_uid_repaired

An entry_uid is empty or repeats an earlier one.

schema_v2_logic_derived_condition_uid_repaired, schema_v2_logic_derived_condition_uid_unmatched

A derived_from_condition_uid names a repaired row, or more entries derive from a condition_uid than rows have it.

schema_v2_logic_write_entry_pm_property_ref_stale_dropped

A write to a PME Property has no matching condition row.

schema_v2_logic_predicate_row_malformed

An integer value of a float row cannot become a float.

Other schema_v2_logic_* codes

The Schema v2 decoder rejected or repaired the logic. path is "logic".

property_stack_normalization_rejected

The decoder changed a value with a different meaning, such as a repaired UID, a dropped entry or a write status turned off. path, input and normalized give the change.

property_stack_canonicalized

severity "info"; does not reject. The decoder changed the form of a value with the same meaning, such as 1.0 to 1.

Example

Make the stack TRUE when any condition matches:

import copy

stack = pme.editing.read_pm(stack_uid)["property_stack"]
logic = copy.deepcopy(stack["logic"])
logic["combine_mode"] = "any"
result = pme.editing.update_property_stack(
    stack_uid, logic=logic, expected_digest=stack["digest"],
)
assert result["status"] == "committed", result["diagnostics"]

Notes

  • To change part of an existing stack, submit the read logic with that part changed and the read digest. Keep every other value, each condition_uid, entry_uid and derived_from_condition_uid.

  • Review scope="current_storage" diagnostics before submitting a read logic: the view can already omit entries or turn writes off. Input validation does not undo normalization applied while reading.

  • Current-storage diagnostics are carried into the result as warnings. They do not reject the call. A stack whose logic is None can be replaced.

  • A dry run does not evaluate sources, check runtime writability, execute a Setter, or test a widget.

  • The While True HUD and the saved and registered Property ID are not changed.

  • The call does not save Preferences to disk, add an Undo step, or run the Getter or Setter.

  • An exception raised during the write keeps its traceback and gains a note with the last status. Call read_pm() before retrying.

pme.editing.add_property_stack_row(pm_uid, *, expected_digest=None, dry_run=False)¶

Append an empty condition row, as the editor does.

The new row is enabled and incomplete, with source, op, value and value_type set to None and the label "Condition N", N being its position. No write entry is added until the row has a definition.

Parameters:

  • pm_uid (str) – UID of the Property Stack.

  • expected_digest (str or None) – read_pm()["property_stack"]["digest"].

  • dry_run (bool) – Check and return without writing.

Returns:

The result described under Common result. condition_uid is the new row’s UID, or the UID it would get after a dry run; None when rejected before a candidate exists.

Return type:

dict

Raises:

RuntimeError – The call is not on Blender’s main thread, or PME has not finished loading.

Diagnostics

In addition to Common result:

code

Cause

property_stack_current_storage_requires_explicit_repair

The saved logic cannot be decoded, or reading it repaired meaning or identity (a blocking code or a "repair" normalization). update_property_stack() replaces it.

predicate_row_limit_reached

The stack already has 128 rows.

Example

before = pme.editing.read_pm(stack_uid)["property_stack"]
added = pme.editing.add_property_stack_row(
    stack_uid, expected_digest=before["digest"],
)
assert added["status"] == "committed", added["diagnostics"]
row_uid = added["condition_uid"]

Notes

  • A dry run’s condition_uid is only a candidate until a later call commits.

  • Other rows, write entries, HUD settings and Property IDs are kept.

pme.editing.update_property_stack_row(pm_uid, condition_uid, fields, *, expected_digest=None, dry_run=False)¶

Change one condition row’s source, operator, value, value type, label or enabled state, as the editor does.

Omitted fields are kept. The row’s authoring_state and its derived write entry follow the editor’s rules.

Parameters:

  • pm_uid (str) – UID of the Property Stack.

  • condition_uid (str) – condition_uid of the row. It cannot be changed.

  • fields (dict) – Any of source, op, value, value_type, label and enabled, with the types of a condition row.

  • expected_digest (str or None) – read_pm()["property_stack"]["digest"].

  • dry_run (bool) – Check and return without writing.

Returns:

The result described under Common result. condition_uid is the argument.

Return type:

dict

Raises:

RuntimeError – The call is not on Blender’s main thread, or PME has not finished loading.

Change

Effect

A changed source, op, value or value_type

The row gets the definition. authoring_state becomes complete when the operator accepts the value type and the value fits the operator, otherwise incomplete. The derived write entry is created or updated; a new one has entry_uid "write_<condition_uid>".

Resulting op, value and value_type all None

Source only. The row stays incomplete and its derived write entry is removed.

label only

The write plan is unchanged.

enabled

The derived write entry follows the editor’s rules. Disabling the row turns it off.

A value equal to the saved one is not a change. When nothing changes, the status is unchanged.

Diagnostics

In addition to Common result. All have scope "input".

code

Cause

property_stack_current_storage_requires_explicit_repair

As for add_property_stack_row().

condition_uid_invalid

condition_uid is not a non-empty string.

predicate_row_not_found

No row has condition_uid.

condition_identity_ambiguous

Several rows have condition_uid.

property_stack_row_fields_must_be_a_mapping

fields is not a dict.

property_stack_row_field_unsupported

fields has a key other than the six above.

property_stack_schema_invalid and the other codes of update_property_stack()

The row with fields applied does not match Schema v2 PmeLogicConditionRow. The check runs on the input, and again on a row that became complete. path refers to a one-row logic, such as "logic.predicate_rows[0].value".

predicate_row_source_required

A definition field is given and the row has no source.

predicate_row_operator_unsupported

The resulting op is None while value_type or value is set.

predicate_row_value_type_unsupported

The resulting value_type is None while op is set.

predicate_row_operator_type_mismatch

op does not accept value_type.

predicate_row_value_type_mismatch

value does not fit op and value_type.

write_entry_limit_reached

The definition would add a write entry beyond 128.

Example

Add a row that is true on frame 1:

before = pme.editing.read_pm(stack_uid)["property_stack"]
added = pme.editing.add_property_stack_row(stack_uid,
    expected_digest=before["digest"])
if added["status"] != "committed":
    raise RuntimeError(added)
row_uid = added["condition_uid"]
updated = pme.editing.update_property_stack_row(stack_uid, row_uid, {
    "source": {"kind": "rna_path", "root": "context", "detected_type": "int",
               "readonly": False, "segments": [
                   {"kind": "attr", "name": "scene"},
                   {"kind": "attr", "name": "frame_current"}]},
    "op": "equals", "value": 1, "value_type": "int", "label": "First frame",
}, expected_digest=added["after"]["digest"])
print(updated["status"], updated["diagnostics"])

Notes

  • An empty row accepts label and enabled. A definition requires a non-null source.

  • An operator that needs a value, given without one, leaves the row incomplete and its derived write entry manual_required.

  • Independent write entries, other rows, combine_mode, false_policy, HUD settings and Property IDs are kept.

  • The call does not save Preferences to disk, add an Undo step, or run the Getter or Setter. After unknown or an exception, call read_pm() before retrying.

pme.editing.remove_property_stack_row(pm_uid, condition_uid, *, expected_digest=None, dry_run=False)¶

Remove one condition row and its derived write entry.

The last row can be removed. Independent write entries are kept.

Parameters:

  • pm_uid (str) – UID of the Property Stack.

  • condition_uid (str) – condition_uid of the row.

  • expected_digest (str or None) – read_pm()["property_stack"]["digest"].

  • dry_run (bool) – Check and return without writing.

Returns:

The result described under Common result. condition_uid is the argument.

Return type:

dict

Raises:

RuntimeError – The call is not on Blender’s main thread, or PME has not finished loading.

Diagnostics

In addition to Common result: property_stack_current_storage_requires_explicit_repair, condition_uid_invalid, predicate_row_not_found and condition_identity_ambiguous, as for update_property_stack_row().

Example

current = pme.editing.read_pm(stack_uid)["property_stack"]
removed = pme.editing.remove_property_stack_row(stack_uid, row_uid,
    expected_digest=current["digest"])
pme.editing.update_property_stack_hud(pm_uid, changes, *, expected=None, dry_run=False)¶

Change the While True HUD of a Property Stack, as its Advanced settings do.

Every value is checked before the first write. The HUD is written through the same owner as JSON import and Duplicate, with enabled set last, and read back.

Parameters:

  • pm_uid (str) – UID of the Property Stack.

  • changes (dict) – Field names from While True HUD fields mapped to new values. Fields not given keep their saved values.

  • expected (dict or None) – Any subset of the saved while_true_hud. The call is rejected with stale_property_stack_hud when a value differs.

  • dry_run (bool) – Check and return the candidate without writing.

Returns:

The result described below.

Return type:

dict

Raises:

  • TypeError – changes or expected is not a mapping with string keys, or dry_run is not a bool.

  • ValueError – A field name is unknown, or the UID is missing, invalid, ambiguous or not a Property Stack.

  • RuntimeError – Called off Blender’s main thread, or before PME has finished loading.

Status

Meaning

Diagnostics

code

Cause, and extra keys

stale_property_stack_hud

A value in expected differs. fields.

property_stack_hud_value_invalid

A value the HUD cannot keep: a wrong type, an editor the HUD cannot show in, a display other than LABEL or FRAME, an alignment the display does not offer, a color component outside 0.0 to 1.0, message or icon longer than 256 UTF-8 bytes, a name that is not a Blender icon or @custom icon, or a Blender icon the HUD cannot draw. field, value and message; choices for area_type, display and alignment; size and limit for text length.

invalid_syntax

is_expr is True and message does not compile. field, message, line and column (within message).

icon_not_found

Warning: no custom icon has the @name. The HUD is saved and shows no icon until the icon exists. field and value.

property_stack_hud_write_failed

The write raised. exception_type and message.

property_stack_hud_value_not_retained

A field read back differently. fields, requested and actual.

Example

stack_uid = pme.create_pm(pme.PmCreationSpec("CONDITION", name="X Mirror")).pm_uid
result = pme.editing.update_property_stack_hud(stack_uid, {
    "enabled": True, "message": "X-Axis Mirror", "display": "FRAME",
    "alignment": "LEFT", "icon": "MOD_MIRROR",
    "use_color": True, "color": [0.2, 0.6, 1.0],
})
assert result["status"] == "committed", result["diagnostics"]

Notes

  • The editor moves an alignment the new display does not offer to TOP. This function rejects it instead; give display and alignment together.

  • Changing only is_expr converts message as the editor’s Expression toggle does: Mirror becomes return 'Mirror'. When message is given too, it is saved as given.

  • Text is limited by UTF-8 bytes, not characters: 256 bytes is 85 Japanese characters.

  • An empty Property Stack can have an enabled HUD, as in the editor.

  • logic, its digest and the menu version do not change. The logic functions leave the HUD unchanged.

  • The HUD of a duplicate is copied with enabled off. Export and import carry the HUD in logic.while_true_hud.

  • The call does not save Preferences to disk or add an Undo step.

While True HUD fields¶

changes, expected and read_pm()["property_stack"]["while_true_hud"] use these fields.

Field

Type

Value

enabled

bool

Show the HUD while the Property Stack is True. Default False.

message

str

Text, or an expression when is_expr is True. Empty shows the menu name. At most 256 UTF-8 bytes.

is_expr

bool

message is a description expression (return ...), evaluated in the editor where the HUD is shown. Default False.

area_type

str

The editor that shows the HUD, such as VIEW_3D (default), IMAGE_EDITOR, NODE_EDITOR or PROPERTIES. A value the HUD cannot show in is rejected with the accepted choices.

display

str

LABEL (default): a label. FRAME: a frame around the editor.

alignment

str

LABEL: TOP (default), TOP_LEFT, TOP_RIGHT, CENTER, BOTTOM, BOTTOM_LEFT, BOTTOM_RIGHT. FRAME: the same without CENTER, plus LEFT and RIGHT.

icon

str

A Blender icon name the HUD can draw, an @custom icon, or empty.

use_color

bool

Use color as the accent color. Default False.

color

list[float]

Three components from 0.0 to 1.0. Default [1.0, 1.0, 1.0]. Read back with single precision: 0.2 reads as 0.20000000298023224.

Condition row¶

Schema v2 PmeLogicConditionRow. Every key is required.

Key

Type

Value

condition_uid

str

Local UID, non-empty and unique in the stack. Write entries refer to it.

enabled

bool

A disabled row does not take part in evaluation.

authoring_state

str

"complete" or "incomplete".

label

str

Display name, at most 256 characters.

source

dict or None

The value read. See Value source. None for an empty row.

op

str or None

Operator. See Vocabularies.

bool, int, float, str, list[str] or None

Comparison value. Its shape depends on op.

"bool", "int", "float", "string", "enum" or "enum_set".

A complete row needs a source whose detected_type equals value_type, an op that accepts value_type, and a value of the shape that op requires.

false_policy¶

Value

FALSE request, for derived and manual_write entries

no_op

Only entries that follow the switch write: a derived auto_resolved Boolean entry writes the opposite value, and a derived Enum-set entry with add or remove applies the opposite change. Fixed values are not written.

explicit_off_write

The entries that follow the switch write as under no_op. In addition, an entry with a fixed value writes that same value, and every Enum-set entry with add or remove applies the opposite change.

TRUE and FALSE¶

FALSE behaviour is chosen per setting. With false_policy="no_op", a Boolean auto_resolved entry still writes its inverse on FALSE.

Intended operation

TRUE

FALSE / write-entry choice

Surface or Volume preset

Set both Boolean values

No writes: fixed Boolean entries use manual_resolved

3D Step Snap

Global Snap on, selected transform on, INCREMENT

Turn only the transform off: its Boolean entry is auto_resolved; other fixed values stay manual

UV Step Snap

UV Snap on, selected transform on, INCREMENT

Turn UV Snap off: its Boolean entry is auto_resolved; other fixed values stay manual

For Enum sets, a manual_resolved entry with enum_set_write_mode="replace" and enum_set_write_values=["INCREMENT"] replaces the set on TRUE and makes no FALSE write. Test the Getter against extra set members as well as the desired set. FALSE does not restore a previous state. The editor’s view of the same rules is under What TRUE and FALSE write.
