Slots¶

A slot is one saved item of a menu: a command, a property, a link to another menu, or a layout entry. This page covers the saved fields of a slot, the Slot Editor inputs, and the operations that edit, clear, add, remove, move, exchange and transfer slots. Rows, spacers and Layout Panels of Pop-up Dialogs and Floating Panels are on Layout rows and panels. The menu-level result of read_pm() is on Menus.

Function

Purpose

read_pm()

Returns the menu’s slots under slots, as described in Slot snapshot.

slot_fields()

Describes the inputs update_slots() accepts.

read_slot_inputs()

Returns slots under those input names.

resolve_auto_icons()

Reports whether Auto Icon finds an icon for each slot.

update_slots()

Changes slot contents through the Slot Editor’s save.

clear_slots()

Clears slot contents and keeps the slots.

add_slot()

Adds one default item.

remove_slot()

Removes one item.

move_slot()

Moves one item within its menu.

swap_slots()

Exchanges two items.

transfer_slot()

Moves one item’s contents to another menu.

None. Context Routers use update_router(); Property callbacks are not slots.

Slot modes offered are the modes of the Slot Editor’s mode selector. The Sticky Key, Stack Key, Macro Operator and Modal Operator editors do not save empty slots; clear_slots() returns clear_unsupported there. For the types with their own editor, update_slots() and clear_slots() raise ValueError and the other operations are rejected.

A menu created by pme.create_pm() starts with its editor’s default slots: a Macro Operator has one empty Command step, and a Modal Operator has one On Invoke slot. Further slots are added with add_slot().

Menu slot text¶

A Menu slot’s link is target_pm_uid. The name in text is the display name and the fallback for a link saved by name only. The prefix stores how the linked menu is shown:

text

Meaning

Inputs

Name

No expansion.

expand_menu=False

@Name

Expand the linked menu.

expand_menu=True

@@Name

Expand the linked menu with a frame.

expand_menu=True, use_frame=True

  • A link to a Regular Menu saves its presentation in menu_presentation and no prefix. Links to a Context Router, and Vector Menu links to a Property, also save no prefix. expand_menu=True or use_frame=True given for such a link is not saved; the slot is committed and reports slot_value_not_retained for the field.

  • With an empty menu_presentation, a Regular Menu link whose text starts with @ is read as SUBMENU. Otherwise it is read as BUTTON.

  • The frame belongs to the expanded display. update_slots() raises ValueError for use_frame=True when the resulting expand_menu is False. Setting expand_menu=False on a framed slot saves the plain target name: the slot reads back as expand_menu=False, use_frame=False.

Icon value¶

icon is optional flags followed by an icon name, for example #!^TOOL_SETTINGS. The flags are part of the string, not separate fields.

Flag

Meaning

#

Icon only: no label.

!

Hidden.

^

Checkbox style, where supported.

Flags are read in the order #, !, ^. A flag out of that order is part of the name. The name is a Blender icon identifier such as TOOL_SETTINGS, "" or NONE for no icon, or @filename for a custom PNG icon. An unknown name is saved as given; the slot shows a fallback icon and update_slots() reports icon_not_found.

In a Macro Operator, the editor sets the icon of every Command step when the Macro is registered: BLENDER for a step that runs as an operator step of Blender’s Macro, TEXT for a step that runs as code. An icon input on such a step is replaced. The two kinds of step are described in Operator steps and code steps.

Button background color¶

button_background_color is saved in scene linear color, as Blender’s own color properties are, and converted to sRGB when the button is drawn. A value taken from a hex code or an sRGB color is converted before it is written. Written unchanged, it is drawn lighter than the source color.

def srgb_to_linear(channel):
    if channel <= 0.04045:
        return channel / 12.92
    return ((channel + 0.055) / 1.055) ** 2.4

# sRGB #A83636
color = [srgb_to_linear(value / 255) for value in (0xA8, 0x36, 0x36)]
pme.editing.update_slots(pm_uid, {slot_uid: {
    "button_background_color_enabled": True,
    "button_background_color": color,
}})

  • The color is drawn only while button_background_color_enabled is True.

  • The button’s text color does not change. Whether the text stays readable on the chosen color is checked by the author, against the theme’s button text color (bpy.context.preferences.themes[0].user_interface.wcol_tool.text) and in the drawn menu.

Modal input¶

In a Modal Operator, Command and Property slots store their modal input in icon: hotkey;expression for a Command slot, and hotkey;minimum;maximum;step;expression for a Property slot with a key. The modal_input input edits these values. On those slots the saved modal input replaces any icon input.

Field

Type

Value

hotkey

str

Hotkey string, as in a Hotkey slot. Default "".

property_mode

str

Property slot input method: KEY, MOVE (MOUSEMOVE) or WHEEL (WHEELUPMOUSE). Default KEY.

custom

str

Display Expression: Python expression whose result is shown in the modal overlay.

minimum, maximum, step

float or None

Property range and step. None uses the property’s own value.

  • Fields that are not named keep their saved values.

  • Changing property_mode on a Property slot sets the key of MOVE or WHEEL and keeps the hotkey’s modifiers and the range.

  • Changing to KEY needs an explicit hotkey. Without one the save is rejected with editor_validation.

# invoke_uid and lens_uid are slot UIDs read from the Modal Operator.
pme.editing.update_slots(modal_uid, {
    invoke_uid: {"mode": "INVOKE", "cmd": "view = C.space_data"},
    lens_uid: {"mode": "PROP", "name": "Lens", "prop": "view.lens",
               "modal_input": {"property_mode": "WHEEL", "step": 1.0}},
})

The code of an INVOKE, UPDATE, FINISH or CANCEL slot is the cmd input. A Property slot’s path can start from a variable that an On Invoke slot assigned, as view here; see Share the starting value across slots. The saved icon of the Property slot holds its modal input as text; read_slot_inputs() returns it as modal_input.

Conflict checks¶

expected_version is the session-local menu version from read_pm() or a previous result. It changes only through PME’s versioned editing operations and does not detect every change. expected compares saved values, including changes made outside those operations. After stale_*, read again and reconcile the intended change before retrying.

Operation

Conflict check

update_slots(), clear_slots()

expected_version, and expected mapping each slot UID to any subset of its slot snapshot.

add_slot()

expected_version, and the complete expected returned by a previous call.

remove_slot() on a list

expected_version, and expected with any subset of the target’s snapshot. The dry run returns all of it.

remove_slot(), move_slot(), swap_slots() on a Pop-up Dialog or Floating Panel

expected_version, and the complete expected returned by a previous call.

move_slot() on a list, swap_slots() on fixed slots

expected_version only. expected raises TypeError.

transfer_slot()

The complete expected returned by the same transfer’s dry run, covering both menus. No expected_version.

Pass a returned expected unchanged. Missing fields in a complete snapshot are not filled in.

pme.editing.read_slot_inputs(pm_uid, *, slot_uids=None)¶

Return slots under the input names that update_slots() accepts.

Values are what the Slot Editor loads from the saved slot: the body under cmd, prop or custom, a Menu slot’s prefix as expand_menu and use_frame, a hotkey split into key and modifiers.

Parameters:

  • pm_uid (str) – UID of the menu.

pme.editing.update_slots(pm_uid, edits, *, expected_version=None, expected=None)¶

Change slot contents through the Slot Editor’s save, one slot at a time.

Each slot commits on its own, in the order of edits. The first rejected slot stops the call; earlier commits stay.

Parameters:

  • pm_uid (str) – UID of the menu.

  • edits (dict) – Slot UID mapped to a dictionary of input names and values. Partial: inputs that are not named keep their loaded values. An empty dictionary, or values that the save would store exactly as the slot already has them, leave the slot unchanged.

  • expected_version (int or None) – Menu version the call requires. Rejected with stale_version when it differs.

  • expected (dict or None) – Slot UID mapped to saved field values the slot must have now, any subset of the slot snapshot. Every UID must also be in edits. Checked before the first save and again before each slot. Rejected with stale_slot when a value differs.

Returns:

The slot save result.

Return type:

dict

Raises:

  • TypeError – edits, expected, a slot’s changes or a slot’s expected values are not mappings; expected_version is not a non-negative int; modal_input is not a mapping or names an unknown field.

  • ValueError – The menu UID is missing, invalid or ambiguous; the menu type has its own editor; expected names a slot not in edits; a slot UID is malformed; an input name is unknown, mode is "EMPTY", any is True, or a value fails its type check; modal_input has a non-finite number or is given for a menu that is not a Modal Operator; use_frame is True while the slot’s resulting expand_menu is False. All of these are checked for every slot before the first save.

Example

pm_uid = pme.create_pm(pme.PmCreationSpec("PMENU", name="Tools Pie")).pm_uid
before = pme.editing.read_pm(pm_uid)
slot = before["slots"][0]
result = pme.editing.update_slots(
    pm_uid,
    {slot["uid"]: {
        "mode": "COMMAND",
        "name": "Knife",
        "cmd": "bpy.ops.wm.tool_set_by_id(name='builtin.knife')",
        "auto_icon": True,
    }},
    expected_version=before["version"],
    expected={slot["uid"]: slot},
)
assert result["status"] == "committed", result

Notes

  • Each committed slot increases the menu version once. An unchanged slot writes nothing: no version change, editor hook or refresh. The comparison uses the values the save would store before the editor’s later normalization, so a value that normalization would change back (for example a background color on a menu type that does not use it) is saved and reported committed; its before and after are equal.

  • A committed slot can carry slot_value_not_retained: the save succeeded, and a requested field does not read back as requested. Check the diagnostics of committed slots, not only status.

  • An empty slot edited without mode is saved as COMMAND and reports slot_mode_normalized. A blank name can be filled from the editor’s suggested name. Read the after value instead of assuming an input stayed empty.

  • The editor normalizes the saved slot. before and after show the result. Editor callbacks can change other slots, such as Macro icons, and switching an empty Layout Panel header on adds a slot. These changes appear in side_effects and structure_changes.

  • A Command edit in a Pie Menu or Vector Menu keeps the other slots and their order.

  • An icon-only edit leaves mode and menu_target_uid out; the other settings keep their values.

  • A Layout Panel anchor is a Menu slot. A save on an anchor without a body target is rejected with editor_validation.

  • An exception after a save started keeps its traceback, with a note naming the committed UIDs. A refresh can fail after a slot committed. Call read_pm() before retrying.

  • The call does not save Preferences to disk, add an Undo step, or run the slot. It is not a raw field write or a JSON import.

See also: Link a child menu and keep its icon flags.

  • dry_run (bool) – Check the move and return without writing.

  • header_anchor_uid (str or None) – Pop-up Dialog and Floating Panel: UID of a Layout Panel anchor, to move into its header. Combine it with exactly one of before_uid, after_uid or edge.

The item operation result.

dict

Raises:

  • TypeError – slot_uid or an anchor UID is not a non-empty string; row_ref does not have exactly kind and slot_uid; expected is given for a menu that is not a Pop-up Dialog or Floating Panel; use_spacer or dry_run is not a bool; expected_version is not a non-negative int.

  • ValueError – The menu UID is missing, invalid or ambiguous; the number of position forms is not one; edge is missing, not START or END, or given without row_ref or header_anchor_uid; new_row is not "END"; row_ref has an invalid kind; header_anchor_uid is given for a list; on a list, a UID is malformed.

Example

Move the last item of a list before the first:

  • An item already at the requested position, including a self anchor, returns unchanged. The version does not change and no refresh runs.

  • Pop-up Dialog and Floating Panel: before_uid and after_uid are exact saved positions, including spacer and column boundaries. It returns validated, unchanged or rejected; before / after and the orders stay the saved state and do not predict the move. It does not reserve the position; the call without dry_run checks again.

anchor_identity_unconfirmed, destination_anchor_required

The anchor is not found, or a non-empty destination got no position.

slot_not_found, structural_slot, panel_row, row_not_found, position_not_found, panel_anchor_not_found, header_target_mismatch, header_role_required

The layout source or position is invalid, as in Item operation results.

menu_reference_slot_incompatible, menu_reference_target_mode_not_allowed, menu_reference_self_reference, menu_reference_presentation_not_supported

A Menu slot’s resolved link is not valid at the destination.

menu_reference_unresolved

Warning: the link is missing or ambiguous and keeps its raw value. kind.

slot_edit_conflict

The Slot Editor has an affected item open: the source, a fixed destination, or a layout entry that cleanup would remove or rewrite.

header_layout_disabled

Warning: a header involved has Header Layout off. anchor_uid.

slot_transfer_failed

A write raised. exception_type and message.

slot_transfer_restore_failed, slot_transfer_registration_restore_failed

The restore raised. status is unknown.

transfer_snapshot_failed, transfer_cleanup_failed

Reading the menus or planning the cleanup raised.

transfer_readback_failed, transfer_rows_readback_failed

Reading a side after the call raised. side. That side’s after or after_rows is None; the status stays. Read the menu again instead of repeating a committed transfer.

transfer_refresh_failed

A refresh raised after the call. operation. A committed status stays.

macro_registration_read_failed

Reading Macro registration raised.

Example

Move an item to the end of a list or layout menu, checking first:

destination = pme.editing.read_pm(destination_pm_uid)
position = ({"after_uid": destination["slots"][-1]["uid"]}
            if destination["slots"] else {})
checked = pme.editing.transfer_slot(
    source_pm_uid, source_slot_uid, destination_pm_uid,
    **position, dry_run=True,
)
if checked["status"] == "validated":
    result = pme.editing.transfer_slot(
        source_pm_uid, source_slot_uid, destination_pm_uid,
        **position, expected=checked["expected"],
    )
    print(result["status"], result["moved"], result["effects"], result["loss"])

For a fixed destination, position is {"destination_slot_uid": empty_slot_uid}. For a Panel header, it is {"header_anchor_uid": anchor_uid, "edge": "END"}. For an ordinary row, it is {"row_ref": row_ref, "edge": "END"}.

Notes

  • A fixed source is cleared and keeps its UID and enabled. A Sticky Key source also gets back its On Press or On Release name and an empty command. A list source is removed, even when it is the last item.

  • layout_panel is not transferred. It stays on a fixed source and is lost with a removed list source. loss reports it: kind "layout_panel", value, transferred (False) and source_removed.

  • The destination editor’s icon rule applies: Pop-up Dialogs and Floating Panels keep icon flags, Macro Operators compute the icon, other types drop the flags. A button background color is cleared where the destination does not use it.

  • Regular Menu labels and layout markers can be anchors but not the item transferred. A Layout Panel anchor cannot be transferred; its header items can, also from a header that is off.

  • Layout cleanup covers the insertion and removal boundaries and an emptied source row; unrelated empty rows and distant spacers stay. When the markerless first row becomes empty, the next row marker is absorbed, as in Move. This differs from remove_row(). Moving the last content out can leave an empty menu; moving the last header item out keeps the anchor and its empty header. Read row references again after a transfer.

  • A missing or ambiguous menu link keeps its raw value with menu_reference_unresolved. A uniquely resolved link that is not valid at the destination is rejected before writing.

  • The Slot Editor draft of an affected item rejects the call. Other drafts, the clipboard and the selection stay.

  • A dry run allocates no UID, does not initialize a version, and runs no editor hook or refresh. before and after are the unchanged saved values, and the cleanup and new UIDs are not predicted. Macro icons and registration are observed only after the call.

  • A refresh failure keeps a committed status. The call does not save Preferences to disk or add an Undo step.
