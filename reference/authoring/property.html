Property¶

A Property (menu type PROPERTY) defines one user property: its type, arguments, Enum items, callbacks, storage and Property ID. The definition is read and changed by field name. A Property Stack is described on Property Stack.

Function

Purpose

read_pm()

Returns the definition under property.

update_property()

Changes the definition, storage and Property ID.

See also: Turn a setting into a Property switch.

Reading a Property¶

read_pm(pm_uid)["property"] is the definition under the field names that update_property() accepts, plus registered_property_id, digest and diagnostics. Only the fields that apply to the Property’s type and storage are present; see Property definition. Values are what the editor shows. Reading does not evaluate the Getter.

>>> pme.editing.read_pm(pm_uid)["property"]
{'type': 'BOOL', 'size': 1, 'default': False, 'expand': True,
 'horizontal': True, 'restore_default': False, 'get': None, 'set': None,
 'update': None, 'init': None, 'storage': None, 'property_id': 'my_toggle',
 'property_id_locked': False, 'registered_property_id': 'my_toggle',
 'digest': '42aaaef6...', 'diagnostics': []}

A new Property is a stored Boolean without callbacks.

diagnostics lists problems in the saved definition:

code

Cause, and extra keys

callback_compile_error

A saved callback has a syntax error. field names the callback; severity is "warning".

argument_unreadable

A saved argument is not a Python literal. field names the argument and text holds the saved text. The field shows the editor default instead.

Where the value lives¶

storage decides who owns the value. registered_property_id is the name the Property is registered under.

storage

Value owner

Read

None

Addon Preferences. PME holds one value.

pme.props(registered_property_id).

An ID type name, such as "Object"

Each data-block of that type holds its own value, as an attribute named registered_property_id.

getattr(data_block, registered_property_id). pme.props() does not hold this value: pme.props(registered_property_id) returns None, or the value of a different Property that uses the same ID in Addon Preferences.

 
prop = pme.editing.read_pm(property_uid)["property"]
name = prop["registered_property_id"]
if prop["storage"] is None:  # Addon Preferences: one value
    value = pme.props(name)
    widget = f"L.prop(props(), {name!r})"
else:  # "Object": a value on each object
    value = getattr(bpy.context.object, name)
    widget = f"L.prop(C.object, {name!r})"

registered_property_id is empty while the Property is disabled. Property ID rules are listed under Property ID and migration.

Property definition¶

The fields of read_pm()["property"]. All except the last three are accepted by update_property(). Default is the value the editor shows when the field was never set. The arguments default, min, max, step, precision, subtype and unit are passed to Blender’s bpy.props function under the same names; None in update_property() returns an argument to its default.

Enum items¶

Each entry of items:

Key

Type

Value

uid

str

UID of an existing item. On input, an existing UID keeps that item’s identity; omit it, or pass "" or None, for a new item.

identifier

str

Required. The value used in scripts. Non-empty, without spaces or |, and unique within the Property.

name

str

Display label. Without |. Omitted or empty: the identifier.

icon

str

Blender icon name. Omitted: "".

items replaces the Enum items in the given order. Enum values follow item order, as in the editor. An identifier cannot be GET, SET, UPDATE, INIT, CLASS, default, min, max, step, precision, subtype or unit. A Multi-Select Enum holds at most 31 items.

FILE_PATH, DIR_PATH, FILE_NAME, BYTE_STRING, PASSWORD, NONE

Unit values¶

unit accepts the identifiers of Blender’s FloatProperty.unit. Blender 5.2 has NONE, LENGTH, AREA, VOLUME, ROTATION, TIME, TIME_ABSOLUTE, VELOCITY, ACCELERATION, MASS, CAMERA, POWER, TEMPERATURE, WAVELENGTH, COLOR_TEMPERATURE and FREQUENCY. The list is read from the running Blender.

Reset rules¶

The editor’s own rules apply, in this order. Values supplied in the same call are applied after these resets.

Change

Effect

type

size becomes 1, multiselect False, horizontal True and items []. default, min, max, step, precision, subtype and unit return to the editor defaults of the new type. Callbacks, expand, restore_default, storage and the Property ID are kept.

items

A default that was never set, or that names the old first item, follows the new first item. A default that names a removed identifier is rejected with default_not_in_items unless default is also given.

multiselect

default returns to the editor default: [] when on, the first item when off.

size

subtype and unit become "NONE". default is cut or padded to the new size; size 1 keeps the first component.

Functions¶

pme.editing.update_property(pm_uid, changes, *, expected_digest=None, dry_run=False)¶

Change a Property’s definition, storage and Property ID as its editor does.

All changes are checked before the first write. If any is rejected, nothing is written. The changes are then saved in three groups, in a fixed order.

Parameters:

  • pm_uid (str) – UID of the Property.

  • changes (dict) – Field name mapped to its new value. Field names are those of Property definition, except the read-only ones. Partial: fields that are not named keep their values, apart from the Reset rules. None returns an argument to the editor default and removes a callback.

  • expected_digest (str or None) – read_pm()["property"]["digest"]. The update is rejected with stale_property when the saved Property has changed.

  • dry_run (bool) – Check the changes and return without writing.

Returns:

The result described below.

Return type:

dict

Raises:

  • TypeError – changes is not a mapping; multiselect, expand, horizontal, restore_default or property_id_locked is not a bool; a callback is not a string or None; property_id is not a string; storage is not None or a non-empty string; items is not a sequence of mappings, an item’s identifier is not a string, or its uid, name or icon is not a string or None; expected_digest is not a string or None; dry_run is not a bool.

  • ValueError – A field name is unknown; type is not one of the five types; size is not an integer from 1 to 32; an item has a key other than uid, identifier, name and icon; the UID is missing, invalid or ambiguous; the menu is not a Property.

  • RuntimeError – The call is not on Blender’s main thread, PME has not finished loading, or PME preferences are unavailable.

storage differs from the saved value.

Example

Turn a new Property into a Float from 0 to 1 with a length unit:

created = pme.create_pm(pme.PmCreationSpec("PROPERTY", name="Bevel Width"))
before = pme.editing.read_pm(created.pm_uid)["property"]
result = pme.editing.update_property(
    created.pm_uid,
    {"type": "FLOAT", "default": 0.1, "min": 0.0, "max": 1.0, "unit": "LENGTH"},
    expected_digest=before["digest"],
)
assert result["status"] == "committed", result["diagnostics"]

Notes

  • When storage changes, the Property ID that is requested or kept is checked against the storage it moves to.

  • No callback is executed by validation, saving or reading. On Init does not run.

  • Stored values follow the normal registration rules: changing type or size discards the stored value, as in the editor. Stored values are not restored after a failure.

  • A committed group, or a group that ends unknown, increments read_pm()["version"].

  • The selected menu and an open draft are not changed.

  • An exception raised while the definition group is saved is re-raised after the saved definition is restored. Its note states whether the restore was confirmed. Call read_pm() before retrying.

  • The call does not save Preferences to disk, add an Undo step, or display the Property.
