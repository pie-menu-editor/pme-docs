メニュー¶

メニュー全体の操作です。メニューの作成・検索・一覧・呼び出し（pme）と、 メニューの保存定義の読み取り、名前・説明・Poll・有効状態・タグの変更、 メニューの複製と削除、メニューを参照している箇所の検索（pme.editing）を扱います。 スロット、レイアウトの行、種類ごとの設定、ホットキー、 Property・Property Stack・Context Router の定義は、それぞれ別のページで扱います。 メニューの書き出しは 書き出しと検証 の export_menus() です。

呼び出しの規則¶

  • メニューは UID で指定します。名前は変わることがあります。 名前で探すときは find_pm() を使い、得た UID を以降の呼び出しに使います。

  • このページの pme.editing の関数はすべて、Blender のメインスレッド以外から呼ばれたとき、 PME の読み込みが完了する前、PME の Preferences を利用できないときに RuntimeError を送出します。

  • このページの関数は、Preferences をディスクへ保存せず、Blender の Undo ステップも追加しません。 メニューを開くのは invoke_pm() だけです。メニューのアクションを実行する関数はありません。

  • status の値の定義は 結果とガード にあります。 編集の一般的な規則は 基本事項 にあります。

メニューの種類の識別子¶

メニューを探す・呼び出す¶

pme.find_pm(name=None, *, uid=None)¶

UID または完全一致の名前で 1 つのメニューを探し、ハンドルを返します。

パラメータ:

  • name (str or None) -- 完全一致で比較するメニュー名。uid を指定しないときだけ使います。

  • uid (str or None) -- メニューの UID。指定すると name は無視されます。

戻り値:

ハンドル。一致するメニューがないときは None。

戻り値の型:

PMHandle or None

例

handle = pme.find_pm("Mesh Tools")
if handle:
    pm_uid = handle.uid

補足

  • 見つからない UID では None を返します。名前での検索は行いません。

  • UID での検索は、その UID を持つ最初のメニューを返します。 複数のメニューが共有する UID は検出しません。

  • PME の Preferences を利用できないとき、 または保留中の Tag の変更を適用できないときは None を返します。

  • ハンドルは呼び出し時点のコピーです。その後の変更には追従しません。

pme.list_pms(mode=None, *, enabled_only=False)¶

すべてのメニューのハンドルをコレクション順に返します。

パラメータ:

  • mode (str or None) -- メニューの種類の識別子（メニューの種類の識別子）。 その種類のメニューだけを返します。None ではすべての種類を返します。 未知の識別子では [] を返します。

  • enabled_only (bool) -- 有効なメニューだけを返します。

戻り値:

メニューごとに 1 つのハンドル。PME の Preferences を利用できないとき、 または保留中の Tag の変更を適用できないときは []。

戻り値の型:

list[PMHandle]

例

for handle in pme.list_pms(mode="PMENU", enabled_only=True):
    print(handle.uid, handle.name, handle.tag)
pme.list_tags()¶

メニューが使っているタグ名を返します。

戻り値:

使われているタグ名を 1 回ずつ。Tag Registry が有効なときはその順、 それ以外は大文字と小文字を区別して並べ替えた順。Untagged は含みません。 PME の Preferences を利用できないとき、 または保留中の Tag の変更を適用できないときは []。

戻り値の型:

list[str]

例

>>> pme.list_tags()
['Modeling', 'Sculpt', 'UV']
pme.invoke_pm(pm_or_name=None, *, name=None, uid=None)¶

ホットキーと同じように、メニューを開く要求を出します。

True は、要求がエラーなく送られたことを表します。 メニューが表示されたことや、アクションが実行されたことは確認しません。

パラメータ:

  • pm_or_name (PMHandle, str or None) -- ハンドルまたはメニュー名。name と uid より優先します。 ハンドルは uid で解決するため、そのメニューや別のメニューが改名された後も、 同じメニューを開きます。uid が空のハンドルは name で解決します。

  • name (str or None) -- メニュー名。pm_or_name と uid を指定しないときに使います。

  • uid (str or None) -- メニューの UID。pm_or_name を指定しないときに使います。 name より優先します。

戻り値:

要求を送ったか。

戻り値の型:

bool

例

opened = pme.invoke_pm(uid=pm_uid)

補足

次の場合は、例外を送出せずに False を返します。

  • 一致するメニューがない。

  • メニューが無効。

  • メニューの Poll または現在のコンテキストが許可しない。

  • Blender のオペレーターの呼び出しが例外を送出した。

  • PME が起動スクリプト（scripts/autorun/、 scripts/register/）を実行中。

メニューを作成する¶

pme.create_pm(spec, *, request_refresh=None)¶

種類の既定の内容でメニューを作成します。

メニューは、エディターの New と同じように作成されます。スロットと設定は作成後に編集します。 スロットは update_slots()、種類ごとの設定は update_settings()、Property は update_property() で編集します。

パラメータ:

  • spec (PmCreationSpec) -- 作成するメニュー。slots は空、 data は None でなければなりません。

  • request_refresh (callable or None) -- メニューの作成と Tree の更新の後、エディターを再描画するために、 引数 "global" で 1 回呼ばれます。None では再描画を要求しません。

戻り値:

新しいメニューの UID、または拒否のコード。

戻り値の型:

PmCreationResult

診断

結果の diagnostics は、辞書ではなくコードを持ちます。検査は表の順に行います。 spec の検査は、失敗したコードをすべてまとめて報告します。 後の検査は、前の検査に通ったときだけ行います。 refresh_failed 以外のコードは、メニューが作成されなかったことを表します。

コード

原因

spec_shape_invalid

spec が PmCreationSpec でない、または項目の型が誤っている （mode_id か name が str でない、data が str でも None でもない、 slots が tuple でも list でもない、スロットの項目が str でない）。このコードだけが報告されます。

unknown_mode

mode_id が メニューの種類の識別子 にない。

logic_envelope_mode_unsupported

slots または data を指定した CONDITION か ROUTER。

slot_count_exceeds_fixed

スロットが種類の固定数を超えている（PMENU と VMENU は 10、 STICKY は 2、CONDITION と ROUTER は 0）。

slot_count_below_fixed

スロットが 1 つの STICKY。PMENU と VMENU は固定数より少ないスロットを受け付けます。

data_marker_mismatch

data の ? より前の部分が、種類のデータマーカーでない。

data_query_malformed

data の ? より後の組が key=value でない。

unknown_slot_mode

スロットの mode が EMPTY、COMMAND、PROP、MENU、 HOTKEY、CUSTOM、INVOKE、FINISH、CANCEL、 UPDATE のどれでもない。

slots_unsupported_by_create_pm

slots が空でない。

data_unsupported_by_create_pm

data が None でない。

boot_worker_thread_unsupported

PME が起動スクリプトを実行している間に、Blender のメインスレッド以外から呼ばれた。

boot_refresh_callback_unsupported

PME が起動スクリプトを実行している間に request_refresh が指定された。

route_pm_identity_*

保存されたメニューが UID の検査に通らない。例: 複数のメニューが UID を共有するときの route_pm_identity_uid_duplicate。

route_target_rejected

作成先を準備できなかった。

route_dry_run_rejected

準備から書き込みまでの間に、メニューのコレクションが変わったか、 新しい UID が衝突した。

route_apply_failed

メニューの作成で例外が発生した。追加した要素は取り除かれています。 元の例外は Blender のコンソールに出力されます。

route_receipt_invalid

作成処理が有効な結果を返さなかった。

refresh_failed

拒否ではありません。accepted は True です。メニューは作成されましたが、 Tree の更新または request_refresh が例外を送出しました。例外は Blender のコンソールに出力されます。

例

created = pme.create_pm(pme.PmCreationSpec(mode_id="VMENU", name="Mesh Tools"))
print(created.accepted, created.pm_uid, created.diagnostics)
if created.accepted:
    menu = pme.editing.read_pm(created.pm_uid)

補足

  • accepted=True は、メニューが Preferences に存在することを表します。 Preferences のディスク保存、メニューの呼び出し、 実行時にすぐ使えることは意味しません。

  • refresh_failed の後は、メニューを作り直さず、返された UID のメニューを読み取ります。

  • 配置、Auto Tag、キーマップの継承は、現在の一覧の状態でのエディターの New に従います。 新しいメニューがアクティブなメニューになります。

  • 空の name では種類の既定の名前を使います。使用中の名前には .001 のような接尾辞が付きます。

  • route_* の検査より前に拒否された要求は、Preferences を読み取りも変更もしません。

  • メインスレッドの起動スクリプトからの呼び出しでは、保存されたメニューだけを作成します。 ホットキーやエディターの登録と画面更新は、この呼び出しの中では行いません。

  • 名前は大文字小文字と Unicode をそのまま保ちます。 add=["A,B"], remove=["B"] は競合です（ValueError）。 無視される追加も重複の検査には含まれます。名前の長さに追加の制限はありません。

  • 名前の集合が変わらない場合でも、 書き込みが保存されたタグのテキストの順序と重複を正規化することがあります （例: すでに所属している名前の追加、存在しない名前の解除）。 名前の集合ではなく保存値を比べてください。

  • expected は JSON の往復でも保たれます。対象の保存されたタグのテキスト、 参照、projection stamp と、レジストリの定義を範囲とします。 古い expected は書き込みなしで拒否されます。

  • dry run は入力、対象、名前の変換を検査します。 同期、UID の割り当て、新しい定義の予測は行わず、 後の書き込みが成功することも証明しません。

  • 空の変更または空の対象集合では、expected の検査の後に、 同期も画面更新もせずに unchanged を返します。

  • recovery.carrier_matches は保存されたタグのデータを baseline と比べます。 baseline は、同期が失敗したときは "before"、 一括書き込みが失敗したときは "after_synchronize" です。 True が証明するのは保存データの一致だけです。 ロールバックが実行されたかは分からないため、attempted は None です。 一致しても restored_failure としては報告されません。

invalid_saved_value_source

想定した形を持たない、 Router の条件または Property Stack のソース。

invalid_saved_reference

マッピングでない、保存されたターゲットまたはソース。

router_authoring_target_*

デコードできない Router のターゲット。

読み取らず、unscannable にも含まれないもの:

  • Property スロット。Property スロットに書いた props().id は見つかりません。

  • コマンドまたはカスタムスクリプトを実行する Router のターゲット。

  • Property Stack のカスタム Set のテキスト。

  • メニューの Poll と説明のスクリプト。

  • スクリプトファイル、ホットキー、PME の外の Python。
