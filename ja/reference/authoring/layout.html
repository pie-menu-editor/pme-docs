レイアウトの行とパネル¶

Pop-up Dialog（DIALOG）とFloating Panel（FPANEL）は、行、spacer、Layout Panelをメニューの保存リストにスロットとして保存します。 このページの関数は、そのリストを行として読み取り、行、spacer、項目の揃え、Layout Panelを変更します。 単独の項目の追加・削除・移動・編集は スロット、Modeや幅などのメニュー設定は メニューの種類ごとの設定 にあります。

関数

用途

read_pm()

行を rows で返します。

add_row()

既定のボタンを持つ行を追加します。

add_panel()

Layout Panelを持つ行を追加します。

remove_row()

行とその中身をすべて削除します。

move_row()

行を別の行の前後へ移動します。

split_row()

行を、その行のスロットの一つの直前で分割します。

join_rows()

隣接する2行を結合します。

update_row()

行設定を変更します。

update_spacer()

spacerの設定を一つ変更します。必要ならspacerを作成します。

align_slot()

項目を行の左・中央・右の区分に配置します。

保存されるレイアウト¶

保存リストは、左から右、上から下の順に読みます。レイアウトを担うスロットは3種類です。

スロット

保存形式

意味

行マーカー

mode は "EMPTY"、text は row で始まる。例: "row?size=LARGE"

行を開始します。この文字列に行設定が入ります。

spacer

mode は "EMPTY"、text は spacer で始まる。例: "spacer?hsep=COLUMN"

行内の間隔、列境界、揃え境界、subrow境界。 この文字列にspacerの設定が入ります。

Layout Panel アンカー

mode は "MENU" で、layout_panel オプションを持つ

Layout Panelを開始します。同じ行でアンカーより後のスロットがPanel ヘッダーです。

行はマーカーから次のマーカーまでです。最初のマーカーより前のスロットは、マーカーのない先頭行になり、 既定の設定を持ちます。新しいPop-up DialogまたはFloating Panelは、マーカーとボタンを一つずつ持ちます。

行構造を読む¶

read_pm(pm_uid)["rows"] は、Pop-up DialogまたはFloating Panelの行を保存順に並べます。 他の種類のメニューには rows キーがありません。空のメニューは rows == [] です。 read_pm() の slot_uids 引数が絞り込むのは slots だけで、rows は常にメニュー全体を表します。 読み取りでは、マーカーの追加、UIDの修復、バージョンの初期化、レイアウトの変更を行いません。

各行は次の辞書です。

行参照¶

row_ref は {"kind": kind, "slot_uid": uid} で、行を開始するスロットを指します。 kind は、そのスロットが行マーカーなら "marker"、マーカーのない先頭行の先頭スロットなら "first_item" です。row_ref は永続的な行IDではありません。

row_ref は、行が同じスロット・同じkindで始まっている間だけ受け付けられます。 そのスロットが移動・削除されたとき、別のスロットがその前に置かれたとき、マーカーのない先頭行にマーカーが追加されたとき（参照が "first_item" から "marker" に変わる）には一致しなくなります。 古い参照は別の行へ付け替えられず、操作は row_not_found で拒否します。 現在の参照は、直前の結果の after_rows から取るか、読み直して取得してください。

行の操作は、キーがちょうど kind と slot_uid の row_ref を受け付けます。 他のキーがある、またはキーが欠けている場合は TypeError、それ以外の kind は ValueError を送出します。

ステータス¶

値は 結果とガード と同じです。

status

意味

validated

dry_run=True で、呼び出しは受理可能です。何も書き込んでいません。

unchanged

保存変更なし。保存済みのスロットがすでに呼び出しを満たしているか、 書き込み後も expected と同じでした。バージョンは変わりません。

committed

保存済みのスロットが変わり、読み戻されました。バージョンが1増えました。

rejected

何も書き込んでいません。diagnostics が原因を示します。

restored_failure

書き込みが例外を送出し、保存済みのスロットを expected のスナップショットへ復元しました。recovery は "restored" です。

unknown

書き込みが例外を送出し、復元にも失敗しました。recovery は "unknown" です。 再試行の前に read_pm() を呼び出してください。

共通の診断¶

code

原因と追加のキー

row_operation_unsupported

メニューがPop-up DialogでもFloating Panelでもありません。このページのすべての関数 （add_row()、add_panel()、remove_row()、move_row()、 split_row()、join_rows()、update_row()、update_spacer()、 align_slot()）が報告します。

stale_version

expected_version が現在のバージョンと異なります。スロットの操作と同じく、 expected (指定したバージョン) と actual (現在のバージョン)。

stale_popup

expected が現在の保存スロット一式と異なります。

row_not_found

row_ref が現在の行のちょうど一つに一致しません。

slot_not_found

UIDがメニューのスロットを一つに特定しません。

slot_edit_conflict

呼び出しが削除または書き換えるスロットを、Slot Editorで編集中です。

panel_row

この呼び出しはLayout Panelの行またはアンカーには使えません。 該当する場合は各関数の説明にあります。

aligner_without_root

変更によって行の最初の ALIGNER が最初の COLUMN より後になり、 揃えの起点が失われます。行が元からその状態でなかった場合だけ報告します。 column_slot_uid、aligner_slot_uid、message。

popup_<operation>_failed

書き込みが例外を送出しました。<operation> は row_add、panel_add、 row_remove、row_move、row_split、row_join、 row_update、spacer_update、slot_alignment のいずれか、 項目の操作では add、remove、move のいずれかです。 exception_type、message。

popup_restore_failed

expected のスナップショットの復元が例外を送出しました。status は "unknown"。exception_type、message。

refresh_failed

書き込み後のエディターの画面更新が例外を送出しました。status は維持されます。 exception_type、message。

popup_readback_failed

呼び出し後の保存状態の読み取りが例外を送出しました。status と recovery は維持されます。exception_type、message。

書き込み前の検査¶

このページのすべての関数は expected_version、expected、dry_run を受け取ります。

引数

規則

expected_version

None または負でない int。メニューのセッション内バージョン （read_pm()["version"] または結果の version）と異なると、 stale_version で拒否します。bool を含むそれ以外の値は TypeError を送出します。

expected

None、または以前のPopupの結果の expected。通常は同じ呼び出しのdry runが返したものです。 変更せずに渡してください。保存スロット一式を保持するため、バージョンが増えない保存変更も検出します。 異なると stale_popup で拒否します。 絞り込んだ read_pm() の結果、slots の要素、編集したコピーでは代用できません。 JSONの往復後も使えます。マッピングでない値は TypeError を送出します。

dry_run

bool。それ以外の値は TypeError を送出します。True は同じ検査を実行し、validated、unchanged、rejected のいずれかを返します。

dry runは何も書き込みません。UIDもマーカーも作成せず、バージョンも変えず、画面更新もしません。 before_* と after_* の値はどちらも現在の保存状態を表し、作成・削除・移動の一覧は空です。 整理の結果、新しいUID、描画の成功は予測しません。 後の呼び出しは引数を改めて解決し、現在の保存状態を再度検査します。

before = pme.editing.read_pm(pm_uid)
checked = pme.editing.add_row(
    pm_uid, expected_version=before["version"], dry_run=True,
)
if checked["status"] == "validated":
    added = pme.editing.add_row(
        pm_uid, expected_version=checked["version"], expected=checked["expected"],
    )
    print(added["status"], added["after_rows"], added["created_row_refs"])

補足¶

  • バージョンを増やすのは committed だけで、1回の呼び出しにつき1回です。

  • status="unknown" で committed=False でも、何も変わっていないとは限りません。

  • エディターの画面更新は、unchanged または restored_failure で終わるものを含め、 すべての書き込みの後に実行されます。書き込み前に止まる呼び出し（dry run、拒否、 書き込み前に変更なしと判明した呼び出し）は画面更新しません。

  • 最終の読み戻しが例外を送出すると、after_order と after_rows は None になります。行の読み戻しだけが失敗した場合は after_order が残ります。 このとき作成・削除・移動の一覧は空ですが、何も変わっていないことを意味しません。 再試行の前に読み直してください。

  • 選択、無関係なSlot Editorの編集中の内容、行のクリップボードはそのまま残ります。

  • この呼び出しはPreferencesをディスクへ保存せず、Undoステップも追加しません。

レイアウト行の追加・削除・移動・分割・結合¶

エディターの Add Row、Remove Row、Move Row、Split、Join Rows コマンドは、 同じ操作を呼び出します。read_pm()["rows"] または直前の結果の after_rows から、 現在の行参照を渡してください。

pme.editing.add_row(pm_uid, *, before_row_ref=None, after_row_ref=None, expected_version=None, expected=None, dry_run=False)¶

Add Row と同じく、行マーカーと既定のボタンを追加します。

位置は最大一つ指定します。指定しない場合は最後の行の後に追加します。 空のメニューでも同じです。

パラメータ:

  • pm_uid (str) -- Pop-up DialogまたはFloating PanelのUID。

  • before_row_ref (dict or None) -- この行の前に新しい行を挿入します。

  • after_row_ref (dict or None) -- この行の後に新しい行を挿入します。

  • expected_version (int or None) -- 書き込み前の検査 を参照。

  • expected (dict or None) -- 書き込み前の検査 を参照。

  • dry_run (bool) -- 書き込まずに検査して返します。

戻り値:

共通の結果キー で説明する結果。

戻り値の型:

dict

例外:

  • TypeError -- row_ref が、キーをちょうど kind と空でない文字列の slot_uid だけ持つマッピングでない場合、または expected_version、expected、 dry_run の型が誤っている場合。

  • ValueError -- 両方の位置を指定した場合、row_ref のkindが "marker" でも "first_item" でもない場合、またはメニューUIDが存在しない・無効・ 曖昧な場合。

結果

slots は新しいマーカーと新しいボタンを、この順で持ちます。 created_uids は同じ2つのUIDを並べます。created_row_refs は新しい行を持ちます。

診断

row_operation_unsupported、row_not_found、stale_version、 stale_popup と、共通の診断 の書き込み失敗。

例

added = pme.editing.add_row(pm_uid)
marker_uid, button_uid = added["created_uids"]

補足

  • 新しいボタンは、名前が Button <n> でコマンドのないCommandスロットです。 空のメニューには、文字列が row のマーカーとボタン一つが入ります。

  • 新しい行の設定は Add Row に従います。

    • 末尾への追加（最後の行の後への追加を含む）: size は最後の行から取ります。 vspacer も、その行に COLUMN spacerがなければ最後の行から取ります。

    • 行の前: size はその行から取ります。その行が NONE で、その上の行に COLUMN spacerがなければ、新しい行は vspacer="NONE"、それ以外は "NORMAL" です。その行の vspacer は、その行に COLUMN spacerがない限り "NONE" になります。

    • 最後でない行の後: size はその行から取ります。新しい行は vspacer="NONE" です。ただし、その行に COLUMN spacerがある場合は "NORMAL" です。

    • COLUMN spacerを持つ行と、そのすぐ下の行は、この呼び出しで vspacer="NONE" を受け取りません。エディターの行の Spacer メニューも、そこでは NONE を提示しません。そのような行にすでに保存されている NONE は維持されます。

  • before_row_ref がマーカーのない先頭行を指す場合は、まずその行にマーカーを追加し、スロットとその文字列を保ちます。このとき structure_changes に "row_ref" 要素が入ります。after_row_ref ではマーカーを追加しません。

pme.editing.update_row(pm_uid, row_ref, changes, *, scope='row', expected_version=None, expected=None, dry_run=False)¶

1つの行、または行のグループの設定を変更します。

すでに要求した値になっている設定は書き込みません。何も異ならない場合、 結果は unchanged です。

パラメータ:

  • pm_uid (str) -- Pop-up DialogまたはFloating PanelのUID。

  • row_ref (dict or None) -- 行。None は scope="all_rows" のときだけ。

  • changes (dict) -- 行設定の名前と新しい値のマッピング。部分指定で、 指定しない設定は値を保ちます。名前と値は 行設定 にあります。

  • scope (str) -- "row"、"aligned_rows"、"all_rows" のいずれか。 下の「対象範囲」を参照。

  • expected_version (int or None) -- 書き込み前の検査 を参照。

  • expected (dict or None) -- 書き込み前の検査 を参照。

  • dry_run (bool) -- 書き込まずに検査して返します。

戻り値:

共通の結果キー で説明する結果。

戻り値の型:

dict

例外:

  • TypeError -- changes がマッピングでない場合、値のPythonの型が誤っている場合 （fixed_col と fixed_but は bool、それ以外は str）、row_ref が他のscopeで None であるか、キーをちょうど kind と空でない文字列の slot_uid だけ持つマッピングでない場合、または expected_version、expected、dry_run の型が誤っている場合。

  • ValueError -- 名前が行設定でない場合、値がその設定の値の範囲にない場合、 scope が3つの値のいずれでもない場合、row_ref のkindが "marker" でも "first_item" でもない場合、またはメニューUIDが存在しない・無効・ 曖昧な場合。

対象範囲

scope

変更する行

row

row_ref で指定した行。

aligned_rows

vspacer="NONE" でつながる、その行を含む行のグループ。上方向へは、 行が vspacer="NONE" を持つ間たどるため、グループの最上行を含みます。 下方向へは、次の行が vspacer="NONE" を持つ間たどります。

all_rows

マーカーのない先頭行を含むすべての行。row_ref は None でもかまいません。空のメニューは空のままで、unchanged を返します。

結果

slots は対象範囲のすべての行のスロットを持ちます。

診断

code

原因と追加のキー

panel_row

Layout Panel行に対する scope="row" で、vspacer 以外の設定を指定しました。fields にその名前が入ります。

row_fields_skipped

拒否ではありません。広い対象範囲で、Layout Panel行の vspacer 以外の設定を変更しませんでした。row_ref、fields。

slot_edit_conflict

書き換えるマーカーをSlot Editorで編集中です。

ほかに row_operation_unsupported、row_not_found、stale_version、 stale_popup と、共通の診断 の書き込み失敗。

例

before = pme.editing.read_pm(pm_uid)
row_ref = before["rows"][0]["row_ref"]
checked = pme.editing.update_row(
    pm_uid, row_ref, {"size": "LARGE", "fixed_but": True},
    expected_version=before["version"], dry_run=True,
)
if checked["status"] == "validated":
    changed = pme.editing.update_row(
        pm_uid, row_ref, {"size": "LARGE", "fixed_but": True},
        expected_version=checked["version"], expected=checked["expected"],
    )
    print(changed["status"], changed["after_rows"], changed["structure_changes"])

補足

  • Layout Panel行は vspacer だけを受け付けます。

  • scope="all_rows" では、行自身またはその上の行に COLUMN spacerがある場合、 vspacer="NONE" をその行に "NORMAL" として書き込みます。

  • 値はこの補正の後で比較します。変更のない呼び出しは保存文字列、UID、 バージョンをそのまま保ち、画面更新もしません。

  • マーカーのない先頭行は、その設定のいずれかが変わるときだけマーカーを受け取ります。 先頭項目はコマンドの文字列を保ちます。このとき structure_changes に "row_ref" 要素が入ります。

  • 変更したマーカーはエディターのencodeで書き込まれるため、そのマーカーの未知の queryキーが正規化または削除される場合があります。他の保存値は変わりません。

  • align は行設定です。align_slot() による項目の配置ではありません。

pme.editing.update_spacer(pm_uid, *, slot_uid=None, before_uid=None, after_uid=None, prop, value, expected_version=None, expected=None, dry_run=False)¶

spacerの設定を一つ変更します。必要ならspacerを作成します。

対象をちょうど一つ指定します。既存のspacerなら slot_uid、内容スロットの隣のspacerなら before_uid / after_uid です。整理の結果が変更の順序に依存するため、 1回の呼び出しで変更する設定は一つです。

パラメータ:

  • pm_uid (str) -- Pop-up DialogまたはFloating PanelのUID。

  • slot_uid (str or None) -- 既存のspacer。先頭、末尾、項目の間のいずれでもかまいません。

  • before_uid (str or None) -- 内容スロット。同じ行でその直前にあるspacerを変更します。 ない場合は、そこにspacerを作成します。

  • after_uid (str or None) -- 内容スロット。同じ行でその直後にあるspacerを変更または作成します。

  • prop (str) -- "hsep" または "subrow"。

  • value (str) -- prop の値。 spacerの設定 を参照。

  • expected_version (int or None) -- 書き込み前の検査 を参照。

  • expected (dict or None) -- 書き込み前の検査 を参照。

  • dry_run (bool) -- 書き込まずに検査して返します。

戻り値:

共通の結果キー で説明する結果。

戻り値の型:

dict

例外:

  • TypeError -- value が文字列でない場合、対象のUIDが空でない文字列でない場合、 または expected_version、expected、dry_run の型が誤っている場合。

  • ValueError -- prop がspacerの設定でない場合、value がその値の範囲にない場合、対象がちょうど一つでない場合、またはメニューUIDが存在しない・無効・曖昧な場合。

結果

slots は、設定が変わるspacer、対象のspacer、作成したspacerを持ちます。

診断

code

原因と追加のキー

spacer_required

slot_uid が行マーカーまたは内容スロットを指しています。

content_slot_required

before_uid または after_uid がspacerまたは行マーカーを指しています。

panel_row

Layout Panel行で、対象がアンカーである、prop が subrow である、または値が hsep="COLUMN" です。

aligner_without_root

共通の診断 を参照。

slot_edit_conflict

書き換えまたは削除するspacerかマーカーをSlot Editorで編集中です。

ほかに row_operation_unsupported、slot_not_found、stale_version、 stale_popup と、共通の診断 の書き込み失敗。

例

    pm_uid, after_uid=slot_uid, prop="hsep", value="SPACER",
)

補足

  • 隣接するspacerはその場で更新します。use_spacer=True の add_slot() は、 代わりにspacerを挿入します。

  • 隣のスロットは同じ行にある必要があります。先頭と末尾の位置も受け付けます。 マーカーのない先頭行の先頭項目の前にspacerを作成しても、行マーカーは追加しません。

  • すべての設定が NONE になったspacerは削除します。隣接するspacerがないときの NONE は unchanged を返します。

  • subrow="END" を持つspacerに hsep="COLUMN" を設定すると、その END を解除します。

  • hsep="COLUMN" は、この行と次の行が vspacer="NONE" を持つ場合、それぞれに vspacer="NORMAL" も設定します。先頭行は変更しません。

  • 行で唯一の COLUMN spacerを別の hsep に変えると、行内の全spacerの subrow を解除します。

  • subrow を BEGIN から NONE に変えると、行内の次の END も解除します。ただし、その前に BEGIN または COLUMN がある場合は解除しません。

  • subrowに COLUMN spacerは必須ではありません。

  • Layout Panelのヘッダーにあるspacerは、Header LayoutがOFFでも変更できます。 この変更でHeader LayoutはONになりません。

補足

  • COLUMN spacerのある行では、項目は最初の COLUMN より前にある必要があり、 その後に ALIGNER があってはなりません。それ以外の場合は、 update_spacer() で境界を編集します。この制限は align_slot のもので、保存レイアウトの制限ではありません。

  • None は、項目が COLUMN より後にある場合も、行の最初と最後の ALIGNER (最大2つ) を削除します。インポートしたデータにある、それ以外の ALIGNER spacerは残ります。

  • 隣接するspacerは、その後エディターの規則で統合されます。

  • Layout Panelのヘッダーの揃えは、Header LayoutがOFFでも変更できます。 この変更でHeader LayoutはONになりません。

Layout Panelを作成し、ヘッダーを編集する¶

Layout Panelは、Pop-up DialogまたはFloating Panelの折りたたみ可能な区画です。1行を占めます。 アンカーはMenuスロットで、その参照先メニューがPanelの本文を提供します。同じ行でアンカーより後のスロットがPanel ヘッダーになります。Panelのアンカーとヘッダーは、行とともに移動・削除されます （move_row()、remove_row()）。アンカーを単独の項目として削除・移動・ 交換することはできません（panel_row）。Layout Panel行は分割も結合もできません。

pme.editing.add_panel(pm_uid, *, before_row_ref=None, after_row_ref=None, expected_version=None, expected=None, dry_run=False)¶

Add Panel と同じく、既定のLayout Panel アンカーを持つ行を追加します。

位置は最大一つ指定します。指定しない場合は最後の行の後に追加します。 空のメニューでも同じです。

パラメータ:

  • pm_uid (str) -- Pop-up DialogまたはFloating PanelのUID。

  • before_row_ref (dict or None) -- この行の前に新しい行を挿入します。

  • after_row_ref (dict or None) -- この行の後に新しい行を挿入します。

  • expected_version (int or None) -- 書き込み前の検査 を参照。

  • expected (dict or None) -- 書き込み前の検査 を参照。

  • dry_run (bool) -- 書き込まずに検査して返します。

戻り値:

共通の結果キー で説明する結果。

戻り値の型:

dict

例外:

  • TypeError -- row_ref が、キーをちょうど kind と空でない文字列の slot_uid だけ持つマッピングでない場合、または expected_version、expected、 dry_run の型が誤っている場合。

  • ValueError -- 両方の位置を指定した場合、row_ref のkindが "marker" でも "first_item" でもない場合、またはメニューUIDが存在しない・無効・ 曖昧な場合。

結果

slots はアンカーを持ちます。created_uids は新しいマーカーとアンカーを並べます。created_row_refs は新しい行を持ちます。

診断

code

原因と追加のキー

layout_panel_unavailable

Blenderが4.2より古いか、UILayout.panel がありません。 dry runが結果を返す前に検査します。

ほかに row_operation_unsupported、row_not_found、stale_version、 stale_popup と、共通の診断 の書き込み失敗。

例

added = pme.editing.add_panel(pm_uid)
anchor_uid = added["slots"][0]["uid"]

補足

  • アンカーは、名前が Panel で、参照先・アイコン・ボタンの背景色を持たない Menuスロットです。layout_panel は新しい idname (layout_panel_<id>) を持ち、default_closed と use_header_layout は False です。ヘッダーは空です。

  • 新しい行の size と vspacer は、add_row() と同じく Add Row に従います。そのうえで、新しい行とその次の行が vspacer="NONE" を持つ場合は vspacer="NORMAL" にします。

  • before_row_ref がマーカーのない先頭行を指す場合は、その行にマーカーを追加し、スロットとその文字列を保ちます。

  • アンカーの名前と menu_target_uid は、アンカーのUIDを使って update_slots() で設定します。menu_target_uid は、名前と同じ編集か、 それより前に指定してください。本文のメニューがないアンカーへの編集は拒否されます（後述の「Panel設定」を参照）。layout_panel 辞書や行マーカーは手で組み立てません。

Panel設定¶

Panel設定は、アンカーに対する update_slots() の項目 layout_panel_default_closed と layout_panel_use_header_layout です。 どちらも bool だけを受け付けます。

  • update_slots() はSlot Editorと同じ方法でアンカーを保存し、Slot Editorは Menuスロットを本文のメニューがある場合だけ保存します。新しい add_panel() のアンカーのように本文のメニューがないアンカーでは、どの項目を指定しても、すべての編集が拒否されます。 スロットの要素は、エディターのメッセージ "Select the item" を伴う editor_validation を持ちます。menu_target_uid を同じ編集か、それより前の編集で指定してください。 エディターのアンカーメニューは、本文のメニューがなくても Default Closed と Header Layout を変更します。pme.editing の関数はどれも変更しません。

  • ヘッダーが空の状態で layout_panel_use_header_layout をONにすると、ヘッダーにボタンを一つ追加します。

  • 後で空になったヘッダーは空のままです。再度の保存、名前の変更、変わらない True では、ボタンを追加しません。

  • OFFにしても、保存済みのヘッダー項目はすべて残ります。

  • 変更のある保存では、enabled=True を含むエディターのアンカー正規化を適用します。 enabled は update_slots() の項目ではありません。

  • update_slots() は編集を1件ずつ順に保存します。失敗しても、先に保存した編集は元に戻りません。

ヘッダーの位置¶

add_slot()、move_slot()、transfer_slot() は、行の panel["anchor_uid"] である header_anchor_uid と、次の位置のちょうど一つを組み合わせて、 項目をPanel ヘッダーに配置します。

位置

意味

before_uid / after_uid

そのヘッダーの保存済みスロットの前または後。spacerも位置として数えます。

edge="START"

アンカーの直後。

edge="END"

ヘッダーの末尾。ヘッダーが空のときはedgeを使います。

  • header_anchor_uid に対して位置を指定しない、または複数指定した場合、edge が "START" でも "END" でもない場合、header_anchor_uid を row_ref または new_row と併用した場合は ValueError を送出します。

  • Layout Panel行の row_ref は、そのヘッダーを意味しません。panel_row で拒否されます。

  • 通常の行または別のヘッダーからヘッダーへの move_slot() には header_anchor_uid が必要です。ない場合、結果は header_role_required です。同じヘッダー内での before_uid / after_uid による移動には不要です。ヘッダーへの transfer_slot() には常に必要です。

  • ヘッダー内での before_uid / after_uid による add_slot() は、 Header LayoutがONの間は header_anchor_uid なしで動作し、 OFFの間は header_anchor_uid が必要です。

  • swap_slots() は2つのUIDだけを受け取ります。通常の項目とヘッダー項目、 または別々のヘッダーの項目を、整理なしで交換します。

  • アンカーを別のヘッダーへ移動することはできません。ヘッダー内にすでに保存されている 2つ目のアンカーは remove_slot() で削除できます。それを挿入する手段はありません。

  • ヘッダー項目は、Header LayoutがOFFの間も追加・移動・削除できます。呼び出しは Header LayoutをONにしません。このとき結果の diagnostics に、anchor_uid を伴う header_layout_disabled が入ります。Preferencesはこれらの項目を編集用に表示し、実行時のメニューは非表示にします。

  • エディターでは、アンカーのメニューに空のヘッダー用の Add があり、Move はヘッダーの先頭と末尾を提示し、Ctrl+Alt+クリックでヘッダー項目を一つ削除し、 Delete Inactive Header はHeader LayoutがOFFのヘッダーの全項目を削除します。

code

原因と追加のキー

header_layout_disabled

拒否ではありません。そのヘッダーのHeader LayoutがOFFです。anchor_uid。

panel_anchor_not_found

header_anchor_uid がLayout Panel アンカーを指していません。

header_target_mismatch

before_uid / after_uid がそのヘッダーのスロットではありません。

header_role_required

header_anchor_uid なしでヘッダーへ移動または転送しました。

panel_row

挿入先がヘッダーの位置以外のLayout Panel行にある、 header_anchor_uid なしの add_slot() がHeader LayoutがOFFのヘッダーを対象にした、または移動する項目がアンカーです。

 
before = pme.editing.read_pm(pm_uid)
panel = next(row["panel"] for row in before["rows"] if row["panel"])
anchor_uid = panel["anchor_uid"]
checked = pme.editing.move_slot(
    pm_uid, slot_uid, header_anchor_uid=anchor_uid, edge="END",
    expected_version=before["version"], dry_run=True,
)
if checked["status"] == "validated":
    moved = pme.editing.move_slot(
        pm_uid, slot_uid, header_anchor_uid=anchor_uid, edge="END",
        expected_version=checked["version"], expected=checked["expected"],
    )
    print(moved["status"], moved["diagnostics"], moved["after_rows"])

行内の項目の位置¶

Pop-up DialogまたはFloating Panelでは、add_slot()、move_slot()、 transfer_slot() は次の挿入先の形式のいずれか一つを受け取ります。

引数

関数

挿入先

before_uid / after_uid

3つすべて

その保存済みスロットの直前または直後。

row_ref と edge="START" / "END"

move_slot、transfer_slot

その行の左端（マーカーの後）または右端。行は空でもかまいません。Layout Panel行は panel_row で拒否されます。

new_row="END"

move_slot、transfer_slot

新しい最後の行。

header_anchor_uid と位置

3つすべて

Panel ヘッダー。ヘッダーの位置 を参照。

  • 受け付ける形式はちょうど一つです。形式を混在させると ValueError を送出します。 new_row はboolではなく、文字列 "END" です。

  • use_spacer は bool で、既定値は False です。Preferencesの設定は適用されません。

  • before_uid / after_uid は、基準スロットの保存indexを使います。マーカーと spacerは飛ばしません。AとBの間にspacerがあると、after_uid=A と before_uid=B は別の位置です。

  • move_slot() は、すべての形式でエディターの空行とspacerの整理を実行します。 移動した項目はUIDと保存値を保ち、選択と開いているSlot Editorの編集中の内容は、 それぞれの項目に結び付いたままです。

  • すでに満たされている before_uid / after_uid の移動は、自分自身を基準にした場合を含め、 spacer、整理、バージョンの変更、画面更新なしで unchanged を返します。 すでに満たされている行端への移動でも、エディターの画面更新は実行される場合があります。 行の唯一の項目を新しい行へ移動すると、整理の後で unchanged になる場合があります。

  • swap_slots() は2つの項目をUIDと保存値ごと交換し、 空行やspacerの整理はしません。

  • エディターの Move の選択画面は、同じ前後の位置、交換、行端、Add Row を提示します。

before = pme.editing.read_pm(pm_uid)
row_ref = before["rows"][-1]["row_ref"]
checked = pme.editing.move_slot(
    pm_uid, slot_uid, row_ref=row_ref, edge="END",
    expected_version=before["version"], dry_run=True,
)
if checked["status"] == "validated":
    result = pme.editing.move_slot(
        pm_uid, slot_uid, row_ref=row_ref, edge="END",
        expected_version=checked["version"], expected=checked["expected"],
    )
    print(result["status"], result["after_rows"], result["structure_changes"])

Popupの解決済み挿入位置を読む¶

add_slot() と move_slot() のPopupの結果は insertion_position を含みます。 transfer_slot() では result["to"]["insertion_position"] です。 値は呼び出しが解決した位置で、dry runでも書き込みでも同じ方法で記録されます。 呼び出し 前 の保存順にある隙間を表します。

キー

型

値

basis

str

常に "before"。

index

int

0から保存スロット数までの隙間のindex。マーカーとspacerを含みます。

previous_slot_uid

str or None

隙間の直前のスロット。先頭では None。

next_slot_uid

str or None

隙間の直後のスロット。末尾では None。

row_ref

dict or None

previous_slot_uid を含む、呼び出し前の状態の行。index 0では、 マーカーのない先頭行があればその行。それ以外は None。

new_row

str or None

新しい最後の行では "END"、それ以外は None。

保存順が [row, A, COLUMN, B] の場合、Aの後の位置は、Aと COLUMN spacerの間の index 2です。Bの前の位置は、COLUMN spacerとBの間のindex 3です。 隣接するマーカーとspacerのUIDが、境界の両側を区別します。

  • 新しい行への挿入は、呼び出し前の状態の末尾indexを row_ref=None とともに返します。将来の行参照やUIDは割り当てません。

  • 移動元の除去、spacerの挿入、整理によって、最終的なindexは変わる場合があります。 成功後も失敗後も、値は呼び出し前の基準のままです。保存結果は after_* の値と順序が示します。

  • unchanged の移動は、要求された隙間を、移動元のUIDを隣接スロットとして返す場合があります。

  • 位置の解決前の拒否では None です。解決後の拒否は位置を持つ場合があります。呼び出しが許可されるかは status と diagnostics で判断します。 新しい検査が以前の検査の位置を再利用することはありません。

  • swap_slots()、remove_slot()、このページの関数、 他の種類のメニューへの転送は None を返します。

  • この値が記録するのは保存上の挿入境界だけです。列とsubrowの入れ子は木構造として報告しません。dry runは before_rows と after_rows に現在の保存行を入れ、整理の結果を予測しません。
