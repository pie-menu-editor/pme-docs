スロット¶

スロットは、メニューに保存された一つの項目です。 コマンド、プロパティ、別のメニューへのリンク、レイアウト項目のいずれかを表します。 このページでは、スロットの保存フィールド、Slot Editor の入力、スロットを編集・消去・追加・削除・移動・入れ替え・移送する操作を扱います。 Pop-up Dialog と Floating Panel の行、spacer、Layout Panel は レイアウトの行とパネル で扱います。 read_pm() のメニュー単位の結果は メニュー にあります。

関数

用途

read_pm()

メニューのスロットを slots に入れて返します。形式は スロットのスナップショット のとおりです。

slot_fields()

update_slots() が受け付ける入力を説明します。

read_slot_inputs()

スロットをその入力名で返します。

resolve_auto_icons()

Auto Icon が各スロットのアイコンを見つけられるかを報告します。

update_slots()

Slot Editor の保存処理を通してスロットの内容を変更します。

clear_slots()

スロットを残したまま内容を消去します。

add_slot()

既定の項目を1件追加します。

remove_slot()

項目を1件削除します。

move_slot()

項目を1件、同じメニュー内で移動します。

swap_slots()

2項目を入れ替えます。

transfer_slot()

1項目の内容を別のメニューへ移します。

メニューの種類ごとのスロット¶

適用できる操作は、メニューの種類で決まります。 最後の行の種類では read_pm()["editable_slots"] が False です。 これらの種類のスロットは、それぞれ専用の操作で編集します。

選べるスロットモード は、Slot Editor のモード選択にあるモードです。 Sticky Key、Stack Key、Macro Operator、Modal Operator のエディターは空のスロットを保存しません。 これらの種類では clear_slots() が clear_unsupported を返します。 専用エディターを持つ種類では、update_slots() と clear_slots() は ValueError を送出し、ほかの操作は拒否されます。

pme.create_pm() で作成したメニューは、エディターの既定のスロットを持ちます。 Macro Operator は空の Command のステップを1つ、Modal Operator は On Invoke のスロットを1つ持ちます。 スロットを増やすには add_slot() を使います。

Menu スロットの text¶

Menu スロットのリンクは target_pm_uid です。 text の名前は表示名で、名前だけで保存されたリンクの代替にもなります。 接頭辞は、リンク先メニューの表示方法を保存します。

text

意味

入力

Name

展開しません。

expand_menu=False

@Name

リンク先メニューを展開します。

expand_menu=True

@@Name

リンク先メニューを枠付きで展開します。

expand_menu=True、use_frame=True

  • Regular Menu へのリンクは、表示方法を menu_presentation に保存し、接頭辞を保存しません。 Context Router へのリンクと、Vector Menu から Property へのリンクも接頭辞を保存しません。 このようなリンクに指定した expand_menu=True や use_frame=True は保存されません。 スロットは committed になり、その項目について slot_value_not_retained を報告します。

  • menu_presentation が空のとき、text が @ で始まる Regular Menu へのリンクは SUBMENU として読み取られます。それ以外は BUTTON として読み取られます。

  • 枠は展開表示に属します。 結果の expand_menu が False になるとき、update_slots() は use_frame=True に対して ValueError を送出します。 枠付きのスロットに expand_menu=False を設定すると、接頭辞のないリンク先の名前を保存します。 読み戻すと expand_menu=False、use_frame=False です。

アイコンの値¶

icon は、省略できるフラグと、その後に続くアイコン名です。例: #!^TOOL_SETTINGS。 フラグは文字列の一部で、別のフィールドではありません。

フラグ

意味

#

アイコンのみ。ラベルを表示しません。

!

非表示。

^

チェックボックス風の表示 (対応する場所のみ)。

フラグは #、!、^ の順に読み取られます。 この順序から外れたフラグは、名前の一部になります。 名前は TOOL_SETTINGS などの Blender のアイコン識別子、アイコンなしを表す "" または NONE、 カスタム PNG アイコン を表す @filename のいずれかです。 未知の名前は指定どおりに保存されます。 スロットは代替アイコンを表示し、update_slots() は icon_not_found を報告します。

Macro Operator では、Macro を登録するときに、エディターが Command のステップすべてのアイコンを設定します。 Blender の Macro のオペレーターのステップとして実行するものは BLENDER、コードとして実行するものは TEXT です。 これらのステップへの icon の入力は置き換えられます。 2種類のステップは オペレーターのステップとコードのステップ で説明しています。

ボタンの背景色¶

button_background_color は、Blender 自身の色のプロパティと同じく scene linear で保存され、ボタンを描くときに sRGB へ変換されます。 16進のカラーコードや sRGB の色から取った値は、書き込む前に変換します。 変換せずに書き込むと、元の色より明るく描かれます。

def srgb_to_linear(channel):
    if channel <= 0.04045:
        return channel / 12.92
    return ((channel + 0.055) / 1.055) ** 2.4

# sRGB #A83636
color = [srgb_to_linear(value / 255) for value in (0xA8, 0x36, 0x36)]
pme.editing.update_slots(pm_uid, {slot_uid: {
    "button_background_color_enabled": True,
    "button_background_color": color,
}})

  • 色が描かれるのは、button_background_color_enabled が True の間だけです。

  • ボタンの文字色は変わりません。 選んだ色の上で文字が読めるかは、作者が確かめます。 テーマのボタンの文字色 (bpy.context.preferences.themes[0].user_interface.wcol_tool.text) と比べ、描かれたメニューでも確認します。

モーダル入力¶

Modal Operator では、Command スロットと Property スロットがモーダル入力を icon に保存します。 Command スロットは hotkey;expression、キーを使う Property スロットは hotkey;minimum;maximum;step;expression です。 これらの値は modal_input 入力で編集します。 これらのスロットでは、icon の入力は保存されるモーダル入力に置き換わります。

競合の確認¶

expected_version は、read_pm() または前の結果から得る、セッション内でだけ有効なメニューのバージョンです。 PME のバージョン管理された編集操作でだけ変わり、すべての変更を検出するわけではありません。 expected は保存値を比較するため、それらの操作の外で行われた変更も検出します。 stale_* が返ったら、読み直して意図した変更を調整してから再試行してください。

pme.editing.update_slots(pm_uid, edits, *, expected_version=None, expected=None)¶

Slot Editor の保存処理を通して、スロットの内容を1つずつ変更します。

各スロットは edits の順に、個別に確定します。 最初に拒否されたスロットで呼び出しは止まり、それまでの確定は残ります。

パラメータ:

  • pm_uid (str) -- メニューの UID。

  • edits (dict) -- スロット UID から、入力名 と値の辞書への対応。 部分指定です。指定しなかった入力は、読み込んだ値を保ちます。空の辞書、 または保存してもスロットの現在の値と完全に同じになる値では、スロットは unchanged になります。

  • expected_version (int or None) -- 呼び出しが要求するメニューのバージョン。異なる場合は stale_version で拒否されます。

  • expected (dict or None) -- スロット UID から、そのスロットが現在持っているべき保存フィールドの値への対応。 スロットのスナップショット の任意の一部を使います。 どの UID も edits に含まれている必要があります。 最初の保存の前と、各スロットの前に検査します。 値が異なる場合は stale_slot で拒否されます。

戻り値:

スロット保存の結果。

戻り値の型:

dict

例外:

  • TypeError -- edits、expected、スロットの変更、スロットの期待値のいずれかがマッピングではありません。expected_version が 0 以上の int ではありません。 modal_input がマッピングではないか、未知の項目を指定しています。

  • ValueError -- メニューの UID が欠けている、不正、曖昧のいずれかです。 メニューの種類が専用エディターを持ちます。 expected が edits にないスロットを指定しています。 スロット UID の形式が不正です。入力名が未知、mode が "EMPTY"、any が True、または値が型の検査に失敗しました。modal_input が有限でない数値を含むか、 Modal Operator ではないメニューに指定されています。スロットの結果の expand_menu が False なのに use_frame が True です。 これらはすべて、最初の保存の前に全スロットについて検査します。

例

pm_uid = pme.create_pm(pme.PmCreationSpec("PMENU", name="Tools Pie")).pm_uid
before = pme.editing.read_pm(pm_uid)
slot = before["slots"][0]
result = pme.editing.update_slots(
    pm_uid,
    {slot["uid"]: {
        "mode": "COMMAND",
        "name": "Knife",
        "cmd": "bpy.ops.wm.tool_set_by_id(name='builtin.knife')",
        "auto_icon": True,
    }},
    expected_version=before["version"],
    expected={slot["uid"]: slot},
)
assert result["status"] == "committed", result

補足

  • 確定したスロットごとに、メニューのバージョンが1回増えます。 unchanged のスロットは何も書き込みません。 バージョンの変更、エディターのフック、画面更新もありません。 比較には、エディターが後で正規化する前の、保存処理が保存する値を使います。 そのため、正規化で元に戻る値 (たとえば、背景色を使わないメニューの種類での背景色) は保存され、committed と報告されます。 その before と after は等しくなります。

  • committed のスロットが slot_value_not_retained を持つことがあります。 保存は成功したものの、要求した項目が要求どおりに読み戻されないことを示します。 status だけでなく、確定したスロットの diagnostics も確認してください。

  • mode なしで編集した空のスロットは COMMAND として保存され、 slot_mode_normalized を報告します。 空の name には、エディターが提案する名前が入ることがあります。 入力が空のまま残ると仮定せず、after の値を読んでください。

  • エディターは保存したスロットを正規化します。結果は before と after に示されます。 エディターのコールバックは、Macro のアイコンなど、ほかのスロットを変更することがあります。 空の Layout Panel ヘッダーをオンに切り替えると、スロットが1つ追加されます。 これらの変更は side_effects と structure_changes に現れます。

  • Pie Menu と Vector Menu での Command の編集は、ほかのスロットとその順序を保ちます。

  • アイコンだけを編集する場合は mode と menu_target_uid を省きます。 ほかの設定は値を保ちます。

  • Layout Panel のアンカーは Menu スロットです。本文のリンク先がないアンカーへの保存は editor_validation で拒否されます。

  • 保存の開始後に起きた例外は traceback を保ち、確定した UID を示す注記が付きます。 スロットの確定後に画面更新が失敗することがあります。再試行の前に read_pm() を呼び出してください。

  • この呼び出しは Preferences をディスクに保存せず、Undo ステップを追加せず、 スロットを実行しません。保存フィールドへの直接の書き込みや JSON のインポートとは異なります。

関連項目: 子メニューへリンクし、アイコンのフラグを保つ。

項目操作の結果。 削除した項目の after は None。

dict

下の ステータス を参照。

committed

bool

status が "committed" のときだけ True。

moved

dict or None

確定後: from と to。それぞれ pm_uid と slot_uid を持ちます。 to.slot_uid は受け取った項目です。

expected

dict or None

両方のメニュー、対象の引数、リンク先メニューの情報を含む不透明なスナップショット。 JSON を経由して往復しても有効です。 移動元のスロットが見つかる前に拒否された場合は None。

effects

list[dict]

予測した効果と観測した効果。効果 を参照。

loss

list[dict]

移されない値。補足 を参照。

diagnostics

list[dict]

code と詳細。診断 を参照。

from、to

dict

それぞれ一方の側: pm_uid、保存された項目のコレクションである before と after、changed、version_before と version_after。 to には insertion_position が加わります。Pop-up Dialog と Floating Panel の側には before_rows と after_rows が加わります。読み取れない after の値は None。

ステータス

status

意味

validated

dry_run=True で、移送を受け付けられます。何も書き込まれていません。

committed

両方のメニューが保存されました。各メニューのバージョンは1回増えました。

rejected

何も書き込まれていません。原因は diagnostics に示されます。

restored_failure

書き込みが失敗し、両方の保存された項目のコレクションが以前のスナップショットと一致しています。 Macro の登録は effects に報告されます。

unknown

書き込みが失敗し、復元または読み戻しで以前の状態を確認できませんでした。 判断する前に read_pm() を呼び出してください。自動で再試行しないでください。

効果

kind

値

prediction

destination_fields: 移動先が受け取る保存フィールド。enabled を含みます。 icon_prediction は、移動先がアイコンを計算する場合は "dynamic"、 それ以外は "known"。

registration

Macro Operator の登録。 phase は before、after、recovery のいずれかで、pm_uid と観測した状態を持ちます。

hook

実行されたエディターのフック: pm_uid と hook。

recovery

saved_restored: 失敗の後に両方のメニューが復元されたかどうか。

例

先に検査してから、一覧またはレイアウトのメニューの末尾へ項目を移します。

destination = pme.editing.read_pm(destination_pm_uid)
position = ({"after_uid": destination["slots"][-1]["uid"]}
            if destination["slots"] else {})
checked = pme.editing.transfer_slot(
    source_pm_uid, source_slot_uid, destination_pm_uid,
    **position, dry_run=True,
)
if checked["status"] == "validated":
    result = pme.editing.transfer_slot(
        source_pm_uid, source_slot_uid, destination_pm_uid,
        **position, expected=checked["expected"],
    )
    print(result["status"], result["moved"], result["effects"], result["loss"])

固定枠の移動先では、position は {"destination_slot_uid": empty_slot_uid} です。Panel のヘッダーでは {"header_anchor_uid": anchor_uid, "edge": "END"}、通常の行では {"row_ref": row_ref, "edge": "END"} です。

補足

  • 固定枠の移動元は消去され、UID と enabled を保ちます。Sticky Key の移動元は、 さらに On Press または On Release の名前と空のコマンドに戻ります。一覧の移動元は、 最後の項目であっても削除されます。

  • layout_panel は移されません。 固定枠の移動元には残り、削除される一覧の移動元とともに失われます。 loss がこれを報告します: kind が "layout_panel"、value、transferred (False)、 source_removed。

  • 移動先エディターのアイコンの規則が適用されます。 Pop-up Dialog と Floating Panel はアイコンのフラグを保ち、Macro Operator はアイコンを計算し、ほかの種類はフラグを外します。 移動先がボタンの背景色を使わない場合、背景色は消去されます。

  • Regular Menu のラベルとレイアウトのマーカーは、基準項目にはできますが、移す項目にはできません。 Layout Panel のアンカーは移せません。 そのヘッダーの項目は、オフのヘッダーからでも移せます。

  • レイアウトの整理は、挿入と削除の境界、および空になった移動元の行を対象にします。 無関係な空行と離れた spacer は残ります。 マーカーのない先頭行が空になると、Move と同じく次の行マーカーを吸収します。 これは remove_row() とは異なります。 最後の内容を移すと、空のメニューになることがあります。最後のヘッダー項目を移しても、 アンカーとその空のヘッダーは残ります。移送の後は行参照を読み直してください。

  • 見つからない、または曖昧なメニューのリンクは、menu_reference_unresolved とともに元の値を保ちます。 一意に解決したリンクが移動先で有効でない場合は、書き込みの前に拒否されます。

  • 影響を受ける項目を Slot Editor で編集中の場合、呼び出しは拒否されます。 ほかの編集中の内容、クリップボード、選択は保たれます。

  • dry run は UID を割り当てず、バージョンを初期化せず、エディターのフックも画面更新も実行しません。 before と after は変更前の保存値のままで、整理と新しい UID は予測しません。 Macro のアイコンと登録は、呼び出しの後にだけ観測されます。

  • 画面更新が失敗しても、確定したステータスは維持されます。 この呼び出しは Preferences をディスクに保存せず、Undo ステップも追加しません。
