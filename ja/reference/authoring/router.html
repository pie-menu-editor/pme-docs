Context Router¶

Context Router(mode ID ROUTER)は、順序付きの分岐の一覧と Otherwise を持ちます。 これらの関数は、その保存されたロジックを分岐の UID で読み取り、変更します。 メニューの作成は pme.create_pm() (メニュー)、ホットキーは ホットキー、エディターは Context Router Editor で説明します。

関数

用途

read_pm()

保存されたロジックと digest を router に入れて返します。

update_router()

分岐を UID で変更し、分岐を追加し、Otherwise を変更します。

remove_router_branch()

分岐を 1 つ削除します。

move_router_branch()

分岐を 1 つ、別の分岐の前または後ろへ移動します。

reorder_router_branches()

すべての分岐を指定した順序に並べます。

関連項目: Router の分岐を追加して条件を編集する。

Router を読み取る¶

Router では、read_pm(pm_uid) は router も返します。

キー

型

値

logic

dict or None

保存されたロジック。Router のロジック で説明します。 保存されたロジックを読み取れないときは None。

digest

str

保存されたロジックのテキストの SHA-256 16 進 digest。このページの関数に expected_digest として渡します。

diagnostics

list[dict]

保存されたロジックを読み取れるときは空です。それ以外では問題ごとに 1 要素で、 それぞれ code と address を持ちます。コードは router_authoring_ に、ロジックの検証コード の接尾辞、 または storage_invalid (JSON ではない)、storage_non_object、 storage_not_string、storage_unsupported_version が続いたものです。

新しい Router には分岐がなく、Otherwise は Pass Through に設定されています。

>>> pme.editing.read_pm(router_uid)["router"]
{'logic': {'version': 2, 'branches': [],
           'otherwise': {'name': 'Otherwise',
                         'target': {'action': None, 'fallback_name': ''},
                         'pass': True}},
 'digest': 'e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855',
 'diagnostics': []}

返される辞書はコピーです。変更しても Router は変わりません。 新しい Router には、まだ保存されたロジックのテキストがありません。その digest は空のテキストの digest です。 上のロジックと等しい要求は unchanged を返し、テキストは空のままです。 ロジックを変える書き込みはテキストを保存し、digest を変えます。次の編集の前に読み直してください。

共通の結果キー¶

4 つの編集関数はすべて、次のキーを持つ辞書を返します。

キー

型

値

status

str

下の ステータス を参照してください。

committed

bool

status が "committed" のときだけ True。

pm_uid

str

pm_uid 引数。

dry_run

bool

dry_run 引数。

before

dict or None

呼び出しの開始時に読み取った read_pm()["router"]。Router を解決できなかった、 または先に引数が拒否されたときは None。

after

dict or None

同じ構造で、書き込み後に読み取ったもの。unchanged では before のコピー。 validated のとき、書き込み前に拒否された要求のとき、書き込み後の読み取りに失敗したときは None。

candidate

dict or None

正規化後の、保存される (dry_run=True では保存されるはずの) ロジック全体。 要求が組み立てられる前に拒否されたときは None。

diagnostics

list[dict]

問題または警告ごとに 1 要素: code と path、および 診断 に挙げる詳細。

ステータス¶

status

意味

committed

保存されたロジックのテキストを読み戻し、candidate と等しいことを確認しました。

validated

dry_run=True で、要求を受け付けられます。何も書き込んでいません。

unchanged

結果のロジックが保存されたロジックと等しくなります (分岐がすでに要求した順序にある場合など)。何も書き込んでいません。dry run では代わりに validated を返します。

rejected

何も保存していません。diagnostics が原因を示します。

unknown

書き込みを試み、保存されたテキストが古いロジックとも新しいロジックとも一致しません。 再試行の前に read_pm() を呼んでください。

これらの値の共通の意味は 結果とガード で定義しています。

診断¶

このページのすべての関数が返すコード:

code

原因と追加のキー

dry_run_must_be_a_boolean

dry_run が bool ではありません。path は "dry_run" です。

expected_digest_must_be_a_string

expected_digest が文字列でも None でもありません。

preferences_unavailable

PME の Preferences を読み取れません。

pm_identity_*

UID が Router をちょうど 1 つ指していません。例: pm_identity_uid_not_found、 pm_identity_uid_malformed、pm_identity_uid_duplicate、 別の種類のメニューに対する pm_identity_expected_mode_mismatch。

router_authoring_*

保存されたロジックを読み取れません。これらの要素は read_pm()["router"]["diagnostics"] の要素で、code と address を持ち、path は持ちません。

stale_router_digest

expected_digest が保存されている digest と異なる、または呼び出しが書き込みを準備している間に保存されたロジックが変わりました。

schema_v2_router_logic_*

結果のロジックが規則に反しています。path は "logic" です。 update_router() は address も加えます。 ロジックの検証コード を参照してください。

router_target_menu_unresolved

警告。menu の対象が、対象にできる種類のメニュー 1 つに解決されない UID を指しています。保存は妨げません。severity は "warning"、 path は "logic.branches[<i>].target" または "logic.otherwise.target"、address は {"branch_index": "<i>", "branch_uid": ...} または {"otherwise": "true"}、target_pm_uid はその UID、reason は pm_identity_* のコードです。

router_commit_rejected

保存の段階で、保存されたテキストが変わりませんでした。エンコードしたロジックが最終検査に失敗した (traceback をコンソールに出力)、または書き込み後に読み戻したテキストが変わっていませんでした。status は rejected です。

router_commit_unknown

書き込みを試み、結果を確認できていません。status は unknown です。

router_readback_failed

書き込み後の Router の読み取りで例外が発生しました。after は None です。 traceback はコンソールに出力されます。再試行の前に read_pm() を呼んでください。

refresh_failed

書き込み後のエディターの更新で例外が発生しました。保存は有効です。 traceback はコンソールに出力されます。

address の値は、branch_index と row_index も含めて文字列です。

関数¶

pme.editing.update_router(pm_uid, *, branches=(), otherwise=None, expected_digest=None, dry_run=False)¶

分岐を UID で変更し、分岐を追加し、Otherwise を変更します。

呼び出しで指定していない分岐も含め、結果のロジック全体を書き込みの前に検査します。 1 つでも規則に反すれば、何も保存しません。

パラメータ:

  • pm_uid (str) -- Router の UID。

  • branches (list or tuple of dict) -- 分岐のパッチ。パッチの規則 のとおりに適用されます。

  • otherwise (dict or None) -- 置き換える Otherwise の項目。None なら Otherwise を保持します。

  • expected_digest (str or None) -- read_pm()["router"] の digest。異なる場合、呼び出しは stale_router_digest で拒否されます。

  • dry_run (bool) -- 要求を検査し、書き込まずに候補を返します。

戻り値:

共通の結果キー で説明する結果。

戻り値の型:

dict

例外:

RuntimeError -- Blender のメインスレッド以外から、または PME の読み込みが完了する前に呼ばれた。

パッチの規則

入力

影響

branch_uid を持つ要素

その分岐を更新します。UID はこの Router の分岐を指す必要があります。 1 回の呼び出しで、同じ UID は 1 回だけ使えます。

branch_uid を持たない要素

新しい UID を持つ新しい分岐を末尾に追加します。要素はリストの順に追加されます。

要素で省略した項目

保存値を保持します。新しい分岐では下の既定値を使います。

name、enabled、combine_mode、target の指定

保存値を置き換えます。target は全体が置き換わります。

conditions の指定

分岐の条件の一覧全体を置き換えます。condition_uid を持つ行はその UID を保ちます。持たない行には、呼び出し前にその分岐にあったどの行の UID とも異なる、 新しい UID が割り当てられます。

行の enabled、authoring_state、label の省略

True、"complete"、""。

指定しない分岐

位置を含めて変わりません。

otherwise の省略または None

変わりません。

otherwise の指定

指定したキー (name、target、pass) だけを置き換えます。 target は全体が置き換わります。

新しい分岐の初期値は、name が "Branch <n>" (n は追加後の分岐の数)、 enabled が True、combine_mode が "all"、条件なし、 target が {"action": None, "fallback_name": ""} です。

ステータス

committed、validated、unchanged、rejected、unknown のいずれか。 結果のロジックが保存されたロジックと等しい要求は、新しい Router でも、書き込まずに unchanged を返します。dry_run=True では、同じ要求が validated を返します。

診断

共通のコード に加えて、次のコードを返します。

code

原因と追加のキー

branches_must_be_a_sequence

branches が list でも tuple でもありません。path は "branches" です。

otherwise_must_be_a_mapping

otherwise が dict でも None でもありません。

router_input_must_be_json_values

JSON に変換できない値があります: JSON 以外の型、循環参照、NaN、 無限大。

branch_must_be_a_mapping

branches の要素が dict ではありません。path は "branches[<i>]" です。

branch_uid_invalid

branch_uid が空でない文字列ではありません。

branch_not_found

branch_uid がこの Router のどの分岐も指していません。

duplicate_branch_edit

2 つの要素が同じ branch_uid を指定しています。

conditions_must_be_a_sequence

conditions が list でも tuple でもありません。

condition_must_be_a_mapping

条件行が dict ではありません。path は "branches[<i>].conditions[<j>]" です。

例

既存の Router の No Match を Pass Through にします。

before = pme.editing.read_pm(router_uid)["router"]
result = pme.editing.update_router(
    router_uid, otherwise={"pass": True}, expected_digest=before["digest"],
)
assert result["status"] == "committed", result["diagnostics"]

補足

  • 呼び出し元の辞書は変更しません。

  • validated の候補に含まれる新しい UID は仮の値です。プレビューした内容を保存するには、 同じ branches と otherwise を dry_run=False で渡し直します。 候補で新たに割り当てられた分岐の UID を、既存の分岐として渡さないでください。

  • 分岐の UID は 1 つの Router 内で一意です。remove_router_branch() で空いた UID は、後の新しい分岐に割り当てられることがあります。

  • router_target_menu_unresolved の警告は、validated や committed と一緒に返ることがあります。

  • この呼び出しは、条件の評価、対象の実行、選択中のメニューやエディターの下書きの変更、 Preferences のディスクへの保存、Undo ステップの追加を行いません。

pme.editing.remove_router_branch(pm_uid, branch_uid, *, expected_digest=None, dry_run=False)¶

分岐を 1 つ削除します。

パラメータ:

  • pm_uid (str) -- Router の UID。

  • branch_uid (str) -- 削除する分岐の UID。

  • expected_digest (str or None) -- read_pm()["router"] の digest。

  • dry_run (bool) -- 要求を検査し、書き込まずに候補を返します。

戻り値:

共通の結果キー で説明する結果。

戻り値の型:

dict

例外:

RuntimeError -- Blender のメインスレッド以外から、または PME の読み込みが完了する前に呼ばれた。

ステータス

committed、validated、rejected、unknown のいずれか。

診断

共通のコード に加えて、次のコードを返します。

code

原因と追加のキー

branch_uid_invalid

branch_uid が空でない文字列ではありません。

branch_not_found

branch_uid がこの Router のどの分岐も指していません。

branch_identity_ambiguous

保存された 2 つの分岐が同じ UID を持っています。

例

router = pme.editing.read_pm(router_uid)["router"]
result = pme.editing.remove_router_branch(
    router_uid, router["logic"]["branches"][-1]["branch_uid"],
    expected_digest=router["digest"],
)
assert result["status"] == "committed", result["diagnostics"]

補足

  • 最後に残った分岐も削除できます。

  • ほかの分岐、その条件の UID、Otherwise は保持されます。

  • この呼び出しは、対象の実行、選択中のメニューやエディターの下書きの変更、 Preferences のディスクへの保存、Undo ステップの追加を行いません。

pme.editing.move_router_branch(pm_uid, branch_uid, *, before_uid=None, after_uid=None, expected_digest=None, dry_run=False)¶

分岐を 1 つ、同じ Router の別の分岐の直前または直後へ移動します。

パラメータ:

  • pm_uid (str) -- Router の UID。

  • branch_uid (str) -- 移動する分岐の UID。

  • before_uid (str or None) -- 直前に置く基準の分岐の UID。

  • after_uid (str or None) -- 直後に置く基準の分岐の UID。before_uid と after_uid のどちらか一方だけを指定します。

  • expected_digest (str or None) -- read_pm()["router"] の digest。

  • dry_run (bool) -- 要求を検査し、書き込まずに候補を返します。

戻り値:

共通の結果キー で説明する結果。

戻り値の型:

dict

例外:

RuntimeError -- Blender のメインスレッド以外から、または PME の読み込みが完了する前に呼ばれた。

ステータス

committed、validated、unchanged、rejected、unknown のいずれか。 現在の位置 (branch_uid と等しい基準を含む) は、書き込まずに unchanged を返します。dry_run=True では、同じ要求が validated を返します。

診断

共通のコード に加えて、次のコードを返します。

code

原因と追加のキー

branch_uid_invalid

branch_uid が空でない文字列ではありません。

branch_not_found

branch_uid がこの Router のどの分岐も指していません。

branch_identity_ambiguous

保存された 2 つの分岐が同じ UID を持っています。

exactly_one_branch_anchor_required

before_uid と after_uid の両方が指定された、またはどちらも指定されていません。

branch_anchor_uid_invalid

基準が空でない文字列ではありません。

branch_anchor_not_found

基準がこの Router のどの分岐も指していません。

例

最後の分岐の優先度を最も高くします。

snapshot = pme.editing.read_pm(router_uid)["router"]
branches = snapshot["logic"]["branches"]
result = pme.editing.move_router_branch(
    router_uid, branches[-1]["branch_uid"], before_uid=branches[0]["branch_uid"],
    expected_digest=snapshot["digest"],
)
print(result["status"], result["diagnostics"])

補足

  • 分岐の内容、条件の UID、Otherwise は保持されます。

  • 書き込み後に digest は変わります。次の編集の前に読み直してください。

  • エディターの Branch メニューの Move Up、Move Down、Remove Branch も、 同じ分岐の規則に従います。エディターからの保存では、ほかの保存値にもエディター自身の正規化が適用されます。

  • この呼び出しは、対象の実行、選択中のメニューやエディターの下書きの変更、 Preferences のディスクへの保存、Undo ステップの追加を行いません。

pme.editing.reorder_router_branches(pm_uid, branch_uids, *, expected_digest=None, dry_run=False)¶

1 回の書き込みで、すべての分岐を指定した順序に並べます。

パラメータ:

  • pm_uid (str) -- Router の UID。

  • branch_uids -- Router の分岐の UID をすべて、それぞれ 1 回ずつ、新しい順序で並べたもの。順序のある iterable (list、tuple、generator、 dict.keys())。

  • expected_digest (str or None) -- read_pm()["router"] の digest。

  • dry_run (bool) -- 要求を検査し、書き込まずに候補を返します。

戻り値:

共通の結果キー で説明する結果。

戻り値の型:

dict

例外:

RuntimeError -- Blender のメインスレッド以外から、または PME の読み込みが完了する前に呼ばれた。

ステータス

committed、validated、unchanged、rejected、unknown のいずれか。 現在の順序は、書き込まずに unchanged を返します。 dry_run=True では、同じ要求が validated を返します。

診断

共通のコード に加えて、次のコードを返します。

code

原因と追加のキー

branch_uids_must_be_a_sequence

branch_uids が文字列、bytes、または iterable ではありません。path は "branch_uids" です。

branch_uids_must_be_ordered

branch_uids が set、frozenset などの集合型で、 順序が定まりません。received_type がその型を示します。 dry_run=True でも返ります。

branch_uids_must_list_every_branch_once

一覧が一部だけ、UID が重複している、または分岐の UID ではない値を含みます。 missing は指定されなかった分岐の UID、unknown は分岐の UID ではない指定値を列挙します。

branch_identity_ambiguous

保存された 2 つの分岐が同じ UID を持っています。path は "logic.branches" です。

例

router = pme.editing.read_pm(router_uid)["router"]
order = [branch["branch_uid"] for branch in router["logic"]["branches"]]
result = pme.editing.reorder_router_branches(
    router_uid, list(reversed(order)), expected_digest=router["digest"],
)
assert result["status"] == "committed", result["diagnostics"]

補足

  • 分岐の内容、その UID、Otherwise は保持されます。

  • この呼び出しは、対象の実行、Preferences のディスクへの保存、Undo ステップの追加を行いません。

Router のロジック¶

read_pm()["router"]["logic"]、candidate、update_router() の入力は、 PME の Schema v2 の定義 (ContextRouterLogic、ContextRouterBranch、 ContextRouterConditionRow、PmeLogicConditionRow、 PmeLogicValueSource、ContextRouterTarget、 ContextRouterTargetAction、ContextRouterOtherwise) にある ContextRouterLogic の形を使います。値は通常の JSON の値です。

{'branch_uid': 'branch_1', 'name': 'Edit Mesh', 'enabled': True,
 'combine_mode': 'all',
 'conditions': [{'condition_uid': 'cond_1', 'enabled': True,
                 'authoring_state': 'complete', 'label': 'Condition',
                 'source': {'kind': 'rna_path', 'root': 'context',
                            'detected_type': 'enum', 'readonly': True,
                            'segments': [{'kind': 'attr', 'name': 'mode'}],
                            'owner_type': None},
                 'op': 'equals', 'value': 'EDIT_MESH', 'value_type': 'enum'}],
 'target': {'action': {'type': 'menu', 'value': 'pm_yp6o3mbh', 'opts': {}},
            'fallback_name': 'Mesh Tools'}}

ロジックオブジェクト¶

キー

型

値

version

int

2。

branches

list[dict]

優先順位順の分岐。一致した最初の有効な分岐が選ばれます。最大 256。

otherwise

dict

どの分岐にも一致しないときの動作。Otherwise を参照してください。

分岐¶

キー

型

値

branch_uid

str

この Router 内の分岐の identity ("branch_1" など)。

name

str

表示名。最大 256 文字。空の名前は "Branch <n>" として保存されます (n は 1 から数えた分岐の位置)。

enabled

bool

False の分岐は、内容を保ったまま飛ばされます。

combine_mode

str

"all": 評価するすべての条件が一致する必要があります。"any": 1 つ一致すれば十分です。

conditions

list[dict]

条件行。最大 256。条件の UID は分岐内で一意です。評価できる条件のない分岐は一致しません。

target

dict

分岐が一致したときに実行するもの。対象 を参照してください。

セグメント

意味

{"kind": "attr", "name": <str>}

属性アクセス。name は _ で始まらない ASCII の識別子です。

Otherwise¶

キー

型

値

name

str

表示名。最大 256 文字。空の名前は "Otherwise" として保存されます。

dict

Run Otherwise で使う対象。分岐の対象と同じ形です。

bool

True: Pass Through。どの分岐にも一致しないとき、Router は何も実行せず、 ホットキーは同じキーの次のメニュー、次に Blender へ渡ります。対象は保持されますが使われません。読み取り結果には True のときだけ現れます。 なし、または False: Run Otherwise。

ロジックの検証コード¶

結果のロジックを上の規則で検査します。失敗 1 件につき診断 1 件で、コードは schema_v2_router_logic_ に下の接尾辞が続いたものです。 update_router() の結果では、address が branch_index、branch_uid と、 行の場合は row_index を持ちます。ロジックオブジェクトや Otherwise の問題では空です。 読み取れない保存されたロジックは、同じ接尾辞に接頭辞 router_authoring_ を付けたコードを read_pm()["router"]["diagnostics"] に報告します。
